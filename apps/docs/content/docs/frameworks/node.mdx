title: No framework
description: Use the Flags SDK in a plain Node.js server, a script, or any runtime without a framework package.
---

You do not need a framework package to use the Flags SDK. Install only `flags`, and call three functions of `runtime` at the right moments of your server. A framework package does exactly this for you.

| Function | When | What it does |
| --- | --- | --- |
| `runtime.onInit()` | One time at startup | Initializes the providers of all registered sources and waits for them. Errors are logged, not thrown. |
| `runtime.onInvoke(request, next)` | For each request | Runs `next` in the scope of the request. Flags evaluated inside `next` get the request, and each flag is evaluated one time for each request. Returns the result of `next`. |
| `runtime.onShutdown()` | When the process stops | Waits for running initializations, then closes all providers. |

All three are optional. Without `onInit`, a provider initializes on its first evaluation. Without `onInvoke`, flags get `undefined` as the request.

## Setup

### 1. Install the package

```sh title="Terminal"
npm install flags
```

### 2. Define your flags

Write the source and its flags by hand, as in [Hono](/docs/frameworks/hono) and [Express](/docs/frameworks/express). By convention, the main source of an application is `self`:

```ts title="src/flags/self.ts"
import { TypedInMemoryProvider } from '@openfeature/server-sdk';
import { defineSource } from 'flags';

// Any OpenFeature server provider works. This one needs no account.
export const self = defineSource({
  provider: new TypedInMemoryProvider({
    enableSale: {
      variants: { on: true, off: false },
      defaultVariant: 'off',
      disabled: false,
      // On for alice only
      contextEvaluator: (context) => (context.user === 'alice' ? 'on' : 'off'),
    },
  } as const),
  project: { system: 'in-memory' },
  getEvaluationContext: (request) => ({
    user: request?.cookies?.get('user')?.value ?? 'anonymous',
  }),
});
```

```ts title="src/flags.ts"
import { defineFlag } from 'flags';
import { self } from './flags/self.ts';

// A flag of the source: the provider decides the value
export const enableSale = self.bindFlag('enableSale', {
  defaultValue: false,
  description: 'Shows the summer sale',
});

// An inline flag: your code decides the value
export const betaBanner = defineFlag({
  key: 'betaBanner',
  decide: (request) => request?.cookies?.get('beta')?.value === '1',
  options: [false, true] as const,
  description: 'Shows the beta banner to testers',
});
```

The `'use flags'` directive is optional here. Add it at the top of `src/flags.ts` if you want to write a [flags manifest](#flags-explorer-and-the-manifest) with the CLI. To try the example, install `@openfeature/server-sdk`.

You can also use the folder `flags/sources/self` of the file system API: `flags sync` writes `.flags/self.ts`, and you import it by its path. See [Code generation](/docs/flags/code-generation#without-a-framework-plugin).

### 3. Run each request in `onInvoke`

A plain Node.js HTTP server:

```ts title="src/server.ts"
import { createServer } from 'node:http';
import { runtime } from 'flags/runtime';
import { betaBanner, enableSale } from './flags.ts';

// Initialize the providers before the first request
await runtime.onInit();

const server = createServer((incoming, outgoing) => {
  const url = new URL(incoming.url ?? '/', 'http://localhost');
  const headers = new Headers();
  for (const [name, value] of Object.entries(incoming.headers)) {
    if (typeof value === 'string') {
      headers.set(name, value);
    }
  }

  // Flags evaluated inside onInvoke belong to this request
  void runtime
    .onInvoke({ headers, url }, async () => {
      const sale = await enableSale();
      const beta = await betaBanner();
      return { sale, beta };
    })
    .then(
      (body) => {
        outgoing.setHeader('content-type', 'application/json');
        outgoing.end(JSON.stringify(body));
      },
      (error: unknown) => {
        outgoing.statusCode = 500;
        outgoing.end(String(error));
      },
    );
});

server.listen(3000);

// Close the providers when the process stops
process.on('SIGTERM', () => {
  server.close();
  void runtime.onShutdown();
});
```

The first argument of `onInvoke` is a `FlagsRequestInit`: `{ headers?, cookies?, url? }`, each optional. Without `cookies`, the SDK reads the `Cookie` header. A Web `Request` fits as it is, so in a runtime with a `fetch` handler you can write:

```ts
export default {
  fetch: (request: Request) =>
    runtime.onInvoke(request, async () => {
      return Response.json({ sale: await enableSale() });
    }),
};
```

The SDK identifies a request by its `headers` object, so pass the same object for the whole request.

## Optional: the configuration files

You do not need configuration files. Your flags name their source, e.g. `self`, and [overrides](/docs/tooling/overrides) work with `FLAGS_SECRET`, or on Vercel, without them.

Add `flags/hooks.ts` when you want OpenFeature hooks for every flag. It has a default export. Add `flags/config.json` for the static settings, e.g. the setting `overrides`. Without a framework plugin, nothing loads the files. Call `runtime.configure` at startup, before the first evaluation:

```ts title="src/server.ts"
import { runtime } from 'flags/runtime';
import settings from './flags/config.json' with { type: 'json' };
import hooks from './flags/hooks.ts';

runtime.configure({ hooks, settings });
await runtime.onInit();
```

The files look the same as in every framework. `flags sync` and `flags watch` also read `flags/config.json`. The SDK reads it at runtime only when you pass it as `settings`. See [Configuration](/docs/flags/configuration).

## Scripts and background jobs

Flags also work outside of a request, for example in a cron job or a CLI script. The request is then `undefined`, so `getEvaluationContext` must not need it. Pass what the flag needs with `evaluationContext`:

```ts title="scripts/report.ts"
import { defineFlag } from 'flags';

const detailedReport = defineFlag({
  key: 'detailedReport',
  decide: (_request, context: { teamSlug: string }) => context.teamSlug === 'acme',
});

// No request: the call side gives the evaluation context
const detailed = await detailedReport({ evaluationContext: { teamSlug: 'acme' } });
```

See [Evaluation context](/docs/flags/evaluation-context).

## Flags Explorer and the manifest

Put your flags in modules that start with `'use flags'`, then write the manifest with the CLI:

```sh title="Terminal"
npx flags manifest
```

It imports the `'use flags'` modules of the current directory (or of `flags manifest [dir]`) with Node.js and writes `flags-manifest.json`. Run it on TypeScript sources with Node.js 22.18 or newer, or on the output of `tsc`. Overrides of Flags Explorer work without extra code: the SDK reads the `flag-overrides` cookie of each request in `onInvoke`. See [Flags manifest](/docs/tooling/flags-manifest) and [CLI](/docs/tooling/cli).
