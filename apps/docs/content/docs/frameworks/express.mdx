title: Express
description: Use the Flags SDK in an Express app with one middleware.
---

`@flags-sdk/express` is an Express middleware. It runs each request in `runtime.onInvoke`, so that flags know the request, and it configures the SDK with your optional configuration, e.g. the hooks of `flags/hooks.ts`. Your route handlers import only `flags`.

## Setup

### 1. Install the packages

```sh title="Terminal"
npm install flags @flags-sdk/express
```

The middleware supports Express 4 and newer.

### 2. Define your flags

Without a bundler, nothing generates `flags:self`, so you write the source and its flags by hand. By convention, the main source of an application is `self`. Create `src/flags/self.ts`:

```ts title="src/flags/self.ts"
import { TypedInMemoryProvider } from '@openfeature/server-sdk';
import { defineSource } from 'flags';

// The source of the flags of this app. The in-memory provider needs no
// account. Any OpenFeature server provider works.
export const self = defineSource({
  provider: new TypedInMemoryProvider({
    enableSale: {
      variants: { on: true, off: false },
      defaultVariant: 'off',
      disabled: false,
      // On for alice only
      contextEvaluator: (context) => (context.user === 'alice' ? 'on' : 'off'),
    },
  } as const),
  project: { system: 'in-memory' },
  // Runs one time for each request
  getEvaluationContext: (request) => ({
    user: request?.cookies?.get('user')?.value ?? 'anonymous',
  }),
});
```

Then create `src/flags.ts` with the flags. It is the same file as in the [other frameworks](/docs/frameworks#without-a-bundler-sources-by-hand):

```ts title="src/flags.ts"
'use flags';

import { defineFlag } from 'flags';
import { self } from './flags/self.ts';

// A flag of the source: the provider decides the value
export const enableSale = self.bindFlag('enableSale', {
  defaultValue: false,
  description: 'Shows the summer sale',
});

// An inline flag: your code decides the value
export const betaBanner = defineFlag({
  key: 'betaBanner',
  decide: (request) => request?.cookies?.get('beta')?.value === '1',
  options: [false, true] as const,
  description: 'Shows the beta banner to testers',
});
```

`'use flags'` marks a module that exports only flags, for the [flags manifest](/docs/tooling/flags-manifest). That is why the source has its own module. To try the example, install `@openfeature/server-sdk`. For a real project, use the provider of your flag management system, for example `new VercelProvider()` of [Vercel Flags](/docs/providers/vercel).

<Callout type="info">
  You can also use the folder `flags/sources/self` of the [file system API](/docs/flags/code-generation) without a bundler: `flags sync` writes `.flags/self.ts`, and you import it by its path, e.g. `import { enableSale } from '../.flags/self.ts'`. See [Code generation](/docs/flags/code-generation#without-a-framework-plugin).
</Callout>

### 3. Add the middleware

```ts title="src/server.ts"
import { flags } from '@flags-sdk/express';
import express from 'express';
import { betaBanner, enableSale } from './flags.ts';

const app = express();

// Each request runs in runtime.onInvoke
app.use(flags());

app.get('/', async (_request, response) => {
  const sale = await enableSale();
  const beta = await betaBanner();
  response.json({ sale, beta });
});

app.listen(3000);
```

Send the cookie `user=alice` to see the sale, and `beta=1` to see the beta banner. Flags evaluated after an `await` in a handler still belong to the same request, and each flag is evaluated one time for each request.

The middleware converts the Node.js headers into Web `Headers` and builds the URL from the `Host` header and `originalUrl`, so `getEvaluationContext` gets the same `FlagsRequest` as in every other framework. Node.js 22.18 or newer runs the TypeScript source directly with `node src/server.ts`.

## Optional: the configuration files

You do not need configuration files. Your flags name their source, e.g. `self`, and [overrides](/docs/tooling/overrides) work with `FLAGS_SECRET`, or on Vercel, without them.

Add `flags/hooks.ts` when you want OpenFeature hooks for every flag, or `flags/overrides.ts` for the options of overrides. Each file has a default export. Express often runs without a bundler, so nothing loads the files for you. Pass them to the middleware: `app.use(flags({ config: { hooks } }))`.

```ts title="src/flags/hooks.ts"
import type { Hook } from 'flags';

const hooks: Hook[] = [
  {
    after: (context, details) => {
      console.log(`${context.flagKey} = ${JSON.stringify(details.value)}`);
    },
  },
];

export default hooks;
```

```ts title="src/server.ts"
import hooks from './flags/hooks.ts';

app.use(flags({ config: { hooks } }));
```

The static settings are in `flags/config.json`, e.g. `"selfSource": false`. `flags sync` and `flags watch` read it. The middleware does not read it.

See [Configuration](/docs/flags/configuration) for all options.

## Lifecycle

Without extra code, a provider initializes on its first evaluation. To initialize the providers before the first request, and to close them when the process stops, call the runtime yourself:

```ts title="src/server.ts"
import { runtime } from 'flags';

await runtime.onInit();
const server = app.listen(3000);

process.on('SIGTERM', () => {
  server.close();
  void runtime.onShutdown();
});
```

## Flags Explorer and the manifest

Without a bundler, no plugin serves the manifest in development. Write it with the CLI instead:

```sh title="Terminal"
npx flags manifest
```

- It imports the modules that start with `'use flags'` in the directory (`flags manifest [dir]`, the current directory by default) with Node.js, and writes `flags-manifest.json` into it. It loads `flags/hooks.ts`, `flags/overrides.ts` and `flags/config.json` if it finds them.
- Run it on the source if Node.js can run it (TypeScript with type stripping, Node.js 22.18 or newer), or on the output of `tsc`, which keeps the directive. A bundled output loses the directive.
- `--out <file>` sets the output file.

Overrides of Flags Explorer work as in every framework: the SDK reads the `flag-overrides` cookie of each request. See [Flags manifest](/docs/tooling/flags-manifest), [CLI](/docs/tooling/cli) and [Overrides](/docs/tooling/overrides).

<Callout type="info">
  Without a bundler, nothing appends the self-registration of `'use flags'` modules. Flags created with `source.bindFlag` register their source themselves. If a module exports plain flag objects with a source, call `registerFlags` with its exports.
</Callout>
