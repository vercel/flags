title: TanStack Start
description: Set up the Flags SDK in TanStack Start with one Vite plugin.
---

`@flags-sdk/tanstack-start` connects the Flags SDK to TanStack Start. It gives each flag the current request through `getRequest()`, loads the configuration files of the folder `flags`, lets `redirect()` and `notFound()` pass through, compiles your flags files, generates the modules of `flags:<source>`, and registers your flags for Flags Explorer. It works with the React and the Solid version of TanStack Start. Your code imports only `flags`.

**Requirements:** TanStack Start 1 with Vite 6 or newer.

## Setup

### 1. Install the packages

```sh title="Terminal"
npm install flags @flags-sdk/tanstack-start @vercel/flags-core
```

`@vercel/flags-core` has the provider of [Vercel Flags](/docs/providers/vercel). It needs no OpenFeature package. Use the provider of your flag management system instead, if you have a different one.

### 2. Add the Vite plugin

```ts title="vite.config.ts"
import { flags } from '@flags-sdk/tanstack-start/vite';
import { tanstackStart } from '@tanstack/react-start/plugin/vite';
import viteReact from '@vitejs/plugin-react';
import { nitro } from 'nitro/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [
    nitro(),
    tanstackStart(),
    viteReact(),
    // Compiles the flags files, writes .flags/self.ts,
    // and points flags:self to it
    flags(),
  ],
});
```

No middleware is needed.

### 3. Create the flag in Vercel

With `@vercel/flags-core` in your dependencies, the source `self` uses the provider of Vercel Flags by default: `new VercelProvider()`. You do not create a provider for it.

`VercelProvider` uses the OIDC token of your project. Run `vercel link` and `vercel env pull` once, and create a boolean flag `enableSale` in the dashboard of your project, or with `vercel flags create enableSale --kind boolean`. See [Vercel Flags](/docs/providers/vercel).

Then declare the flag in `app.flags`, in the root of your application, next to `package.json`:

```js title="app.flags"
flag enableSale {
  description: "Shows the summer sale"
  defaultValue: false
}
```

The flags file declares the flags of your code, with their keys, types and default values. Vercel Flags still decides each value. The build reads only the file, so it needs no network and no credentials. Turn on `allowArbitraryExtensions` in `tsconfig.json`, and add `*.d.flags.ts` to `.gitignore`. See [Flags files](/docs/flags/flags-files).

The context is optional. It tells the provider who the user is, e.g. for targeting rules. Add `flags/sources/self/context.ts`. The SDK calls it once per request, and the default provider stays:

```ts title="flags/sources/self/context.ts"
import type { FlagsRequest } from 'flags';

// The evaluation context of all flags of this source, once per request
export default function getEvaluationContext(
  request: FlagsRequest | undefined,
) {
  return { user: request?.cookies?.get('user')?.value ?? 'anonymous' };
}
```

Without `context.ts`, the provider gets only the evaluation context of the call side. In the same way, `provider.ts` replaces the default provider. See [The default source `self`](/docs/flags/code-generation#the-default-source-self).

With another provider, create `flags/sources/self/provider.ts`. To try the SDK without an account, export an in-memory provider of `@openfeature/server-sdk`. See [Code generation](/docs/flags/code-generation#the-folder-of-a-source).

### 4. Use the flag in a loader

Flags run only on the server. Route loaders run on the server and in the browser, so the loader calls a server function:

```tsx title="src/routes/index.tsx"
import { createFileRoute } from '@tanstack/react-router';
import { createServerFn } from '@tanstack/react-start';
import { enableSale } from 'flags:self';

const getSale = createServerFn({ method: 'GET' }).handler(() => enableSale());

export const Route = createFileRoute('/')({
  loader: () => getSale(),
  component: Home,
});

function Home() {
  const sale = Route.useLoaderData();
  return <h1>{sale ? 'Summer sale!' : 'Welcome'}</h1>;
}
```

You can also import the flag from its file. The plugin writes `.flags/self.ts`, the types of `flags:self` in `src/flags/generated.d.ts` (or in `flags/generated.d.ts` if a folder `flags` exists in the root), and `app.d.flags.ts`. Git ignores `.flags` by itself. A new flag in `app.flags` becomes a new export of `flags:self`. See [Code generation](/docs/flags/code-generation).

## Inline flags

An [inline flag](/docs/flags/inline-flags) decides its value in your code. Put inline flags into a module that starts with `'use flags'`:

```ts title="src/flags.ts"
'use flags';

import { defineFlag } from 'flags';

export const betaBanner = defineFlag({
  key: 'betaBanner',
  decide: (request) => request?.cookies?.get('beta')?.value === '1',
  options: [false, true] as const,
  description: 'Shows the beta banner to testers',
});
```

The plugin registers the flags of each module that starts with `'use flags'`, so Flags Explorer finds them. The generated `flags:self` module has the directive already. Both kinds of flags are called in the same way:

```tsx title="src/routes/index.tsx"
import { createFileRoute } from '@tanstack/react-router';
import { createServerFn } from '@tanstack/react-start';
import { enableSale } from 'flags:self';
import { betaBanner } from '../flags';

const getFlags = createServerFn({ method: 'GET' }).handler(async () => {
  const sale = await enableSale();
  const beta = await betaBanner();
  return { sale, beta };
});

export const Route = createFileRoute('/')({
  loader: () => getFlags(),
  component: Home,
});

function Home() {
  const { sale, beta } = Route.useLoaderData();
  return (
    <main>
      {beta ? <p>You see the beta.</p> : null}
      <h1>{sale ? 'Summer sale!' : 'Welcome'}</h1>
    </main>
  );
}
```

Set the cookie `beta=1` to see the beta banner.

## Without flags files

You can also write the source and its flags by hand. Use `defineSource` and `source.bindFlag`. Without flags files, the code generation writes nothing. To turn off the code generation, use `flags({ disableCodeGeneration: true })`.

```ts title="src/flags/self.ts"
import { VercelProvider } from '@vercel/flags-core/openfeature';
import { defineSource } from 'flags';

export const self = defineSource({
  provider: new VercelProvider(),
  project: { system: 'vercel-flags' },
  getEvaluationContext: (request) => ({
    user: request?.cookies?.get('user')?.value ?? 'anonymous',
  }),
});
```

```ts title="src/flags.ts"
'use flags';

import { self } from './flags/self';

export const enableSale = self.bindFlag('enableSale', {
  defaultValue: false,
  description: 'Shows the summer sale',
});
```

Each flag is declared on its source. This is the same code that the SDK compiles a flags file into. See [Flags of a source](/docs/flags/provider-flags).

## Server routes

Server routes can evaluate flags directly in their handlers:

```ts title="src/routes/api/flags.ts"
import { createFileRoute } from '@tanstack/react-router';
import { enableSale } from 'flags:self';
import { betaBanner } from '../../flags';

export const Route = createFileRoute('/api/flags')({
  server: {
    handlers: {
      GET: async () => {
        const sale = await enableSale();
        const beta = await betaBanner();
        return Response.json({ sale, beta });
      },
    },
  },
});
```

The binding reads the request with `getRequest()`, so flags work in server functions, server routes, and the server rendering of pages. Each flag is evaluated one time for each request.

## Optional: the configuration files

You do not need configuration files. Your flags name their source, e.g. `self`, and [overrides](/docs/tooling/overrides) work with `FLAGS_SECRET`, or on Vercel, without them.

Add a file to the folder `flags`, next to `flags/sources`, when you want settings for all flags:

- `flags/hooks.ts`: OpenFeature hooks for every flag, as the default export.
- `flags/config.json`: the static settings, e.g. `"selfSource": false`, or `overrides`: which override cookies the SDK accepts.

The Vite plugin loads the files automatically, from the `flags` folder of your project or of `src`. In development, a change applies without a restart.

```ts title="flags/hooks.ts"
import type { Hook } from 'flags';

const hooks: Hook[] = [
  {
    after: (context, details) => {
      console.log(`${context.flagKey} = ${JSON.stringify(details.value)}`);
    },
  },
];

export default hooks;
```

See [Configuration](/docs/flags/configuration) for all options.

## Signals

`redirect()` and `notFound()` of TanStack Router reach TanStack Start unchanged, also when you throw them from `getEvaluationContext`:

```ts title="flags/sources/self/context.ts"
import { redirect } from '@tanstack/react-router';
import type { FlagsRequest } from 'flags';

export default function getEvaluationContext(
  request: FlagsRequest | undefined,
) {
  if (request?.cookies?.get('blocked')) {
    throw redirect({ to: '/blocked' });
  }
  return { user: request?.cookies?.get('user')?.value ?? 'anonymous' };
}
```

## Flags Explorer and the manifest

- `vite dev` serves the [flags manifest](/docs/tooling/flags-manifest) at `/.well-known/flags/manifest.json`.
- `vite build` writes `flags-manifest.json` into `.output/server`.
- Overrides of Flags Explorer use the `flag-overrides` cookie. See [Overrides](/docs/tooling/overrides).

To show the values of a request in Flags Explorer, write the flag values element yourself; see [Other frameworks](/docs/frameworks/next/flag-values#other-frameworks).

## How it works

- The binding gets the request with `getRequest()` of TanStack Start and recognizes `redirect()` and `notFound()` with `isRedirect()` and `isNotFound()` of TanStack Router.
- TanStack Start has a package for React and one for Solid. The plugin resolves the imports of the binding to the packages of your project.
- The plugin bundles `flags` and `@flags-sdk/tanstack-start` into the server code, so that the aliases reach them, and excludes them from the dependency optimizer of Vite.
- In `vite dev`, the SSR environment runs in a worker of Nitro, so the plugin imports the flags modules in a runnable copy of that environment to build the manifest.

The binding follows the [Flags SDK standard](/docs/standard/framework-bindings).
