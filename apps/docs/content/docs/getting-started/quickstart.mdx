This guide connects Vercel Flags to your application, declares a flag in `app.flags`, and imports it by name:

```ts
import { enableSale } from 'flags:self';

const sale = await enableSale();
```

Pick your framework in the tabs. The setup is the same in each framework.

<Callout>
  Hono, Express and plain Node.js have no bundler. They compile the flags files
  with `node --import flags/register`, and import the flags from the files. See
  [Hono](/docs/frameworks/hono), [Express](/docs/frameworks/express) or [no
  framework](/docs/frameworks/node).
</Callout>

### 1. Install the packages

Install `flags`, the package of your framework, and the OpenFeature provider of Vercel Flags. For another flag management system, see [Use another provider](#use-another-provider).

```sh tab="Next.js" title="Terminal"
npm install flags @flags-sdk/next @vercel/flags-core
```

```sh tab="SvelteKit" title="Terminal"
npm install flags @flags-sdk/sveltekit @vercel/flags-core
```

```sh tab="Nuxt" title="Terminal"
npm install flags @flags-sdk/nuxt @vercel/flags-core
```

```sh tab="TanStack Start" title="Terminal"
npm install flags @flags-sdk/tanstack-start @vercel/flags-core
```

### 2. Add the plugin

The framework package connects the SDK to the request. It also compiles your flags files, and by default it generates the imports `flags:<source>`, e.g. `flags:self`.

```ts tab="Next.js" title="next.config.ts"
import { withFlags } from '@flags-sdk/next/plugin';

export default withFlags({
  // Your Next.js configuration, as usual
});
```

```ts tab="SvelteKit" title="vite.config.ts"
import { flags } from '@flags-sdk/sveltekit/vite';
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [sveltekit(), flags()],
});
```

```ts tab="Nuxt" title="nuxt.config.ts"
export default defineNuxtConfig({
  modules: ['@flags-sdk/nuxt'],
});
```

```ts tab="TanStack Start" title="vite.config.ts"
import { flags } from '@flags-sdk/tanstack-start/vite';
import { tanstackStart } from '@tanstack/react-start/plugin/vite';
import viteReact from '@vitejs/plugin-react';
import { nitro } from 'nitro/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [nitro(), tanstackStart(), viteReact(), flags()],
});
```

### 3. Create the flag in Vercel

With `@vercel/flags-core` in your dependencies, the source `self` uses the provider of Vercel Flags by default. You do not create a provider for it.

Link your application to its Vercel project, and pull its environment variables. The provider uses the OIDC token of the project:

```sh title="Terminal"
vercel link
vercel env pull
```

Then create a boolean flag `enableSale` in the dashboard of your project, or with the CLI:

```sh title="Terminal"
vercel flags create enableSale --kind boolean
```

See [Vercel Flags](/docs/providers/vercel) for an SDK key instead of the OIDC token.

### 4. Declare the flag

Create `app.flags` in the root of your application, next to `package.json`. In SvelteKit, create `src/app.flags`, since SvelteKit type-checks `src` only. Declare the flag with the key that you created in Vercel:

```js title="app.flags"
flag enableSale {
  description: "Shows the summer sale"
  defaultValue: false
}
```

The flags file declares which flags your code knows. Vercel Flags still decides each value, with its rules and rollouts. `defaultValue` is the value when the evaluation fails, e.g. before the flag exists in Vercel. See [Flags files](/docs/flags/flags-files) for the format.

Turn on `allowArbitraryExtensions` in `tsconfig.json`, and let Git ignore the declaration files which the SDK writes next to each flags file:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "allowArbitraryExtensions": true
  }
}
```

```txt title=".gitignore"
*.d.flags.ts
```

### 5. Use the flag

Import the flag from its source, `flags:self`, or from its file, e.g. `import { enableSale } from '../app.flags'`. Call it on the server. It returns a promise of its value.

```tsx tab="Next.js" title="app/page.tsx"
import { enableSale } from 'flags:self';

export default async function Page() {
  const sale = await enableSale();
  return <main>{sale ? <p>Summer sale!</p> : null}</main>;
}
```

```ts tab="SvelteKit" title="src/routes/+page.server.ts"
import { enableSale } from 'flags:self';

export async function load() {
  return { sale: await enableSale() };
}
```

```ts tab="Nuxt" title="server/api/sale.get.ts"
import { enableSale } from 'flags:self';

export default defineEventHandler(async () => ({
  sale: await enableSale(),
}));
```

```tsx tab="TanStack Start" title="src/routes/index.tsx"
import { createFileRoute } from '@tanstack/react-router';
import { createServerFn } from '@tanstack/react-start';
import { enableSale } from 'flags:self';

// Flags run on the server, so the loader calls a server function
const getSale = createServerFn({ method: 'GET' }).handler(() => enableSale());

export const Route = createFileRoute('/')({
  loader: () => getSale(),
  component: Home,
});

function Home() {
  const sale = Route.useLoaderData();
  return sale ? <p>Summer sale!</p> : null;
}
```

Start your development server. The plugin reads your flags files, and writes `.flags/self.ts`, `flags/generated.d.ts` and `app.d.flags.ts` before the first request. It writes them again after each change of a flags file. It uses no network for this, so the build and the type check also work offline and in CI.

<Callout>
  If your application has a `src` directory, the types of `flags:self` go to
  `src/flags/generated.d.ts`. Run `flags sync` before a type check without a
  build, e.g. `"type-check": "flags sync && tsc --noEmit"`.
</Callout>

### 6. Optional: add the evaluation context

The evaluation context tells the provider who the user is, e.g. for targeting rules. Add `flags/sources/self/context.ts` (in SvelteKit, `src/flags/sources/self/context.ts`). The SDK calls it once for each request, even when a page evaluates many flags:

```ts title="flags/sources/self/context.ts"
import type { FlagsRequest } from 'flags';

export default function getEvaluationContext(request: FlagsRequest | undefined) {
  return {
    user: { id: request?.cookies?.get('user-id')?.value ?? 'anonymous' },
  };
}
```

The source `self` keeps the default provider of Vercel Flags, and adds your context. In the same way, `provider.ts` in `flags/sources/self` replaces the default provider. See [The default source `self`](/docs/flags/code-generation#the-default-source-self).

Without `context.ts`, the provider gets only the evaluation context of the call side.

### 7. Optional: decide a flag in code

Not every flag needs a provider. An [inline flag](/docs/flags/inline-flags) decides its value in your code, and gets the same overrides, caching and types. Put inline flags into a module that starts with `'use flags'`:

```ts title="flags.ts"
'use flags';

import { defineFlag } from 'flags';

export const betaBanner = defineFlag({
  key: 'betaBanner',
  decide: (request) => request?.cookies?.get('beta')?.value === '1',
});
```

The `'use flags'` directive lets [Flags Explorer](/docs/tooling/flags-explorer) find these flags. Flags files need no directive: the SDK finds them.

## What happened behind the scenes

The plugin compiles `app.flags` into plain code: one source, and one flag for each flag of the file. You can write the same code by hand, e.g. in `flags.ts`:

```ts title="app.flags (compiled, simplified)"
'use flags';

import { defineSource } from 'flags';
import getEvaluationContext from './flags/sources/self/context.ts';
import { VercelProvider } from '@vercel/flags-core/openfeature';

const source = defineSource({
  provider: new VercelProvider(),
  project: { system: 'vercel-flags' },
  getEvaluationContext,
});

export const enableSale = source.bindFlag('enableSale', {
  description: 'Shows the summer sale',
  defaultValue: false,
});
```

`.flags/self.ts` re-exports the flags of the source `self` from all flags files, e.g. `export { enableSale } from '../app.flags'`. `flags/generated.d.ts` declares the types of `flags:self`, so TypeScript finds them without `paths`.

The import of `context.ts` is there only if you added the file. See [Provider flags](/docs/flags/provider-flags) for the API behind it.

## Use another provider

With another flag management system, or without `@vercel/flags-core`, create the source yourself. A source is a folder `flags/sources/<source>` with one file, and two optional files. The flags stay in your flags files:

```txt
app.flags           which flags exist, with their types and default values
flags/
  sources/
    self/
      provider.ts   which provider evaluates the flags
      context.ts    optional: who the user is, for each request
      hooks.ts      optional: OpenFeature hooks of the source
```

`provider.ts` exports any OpenFeature server provider. See [Code generation](/docs/flags/code-generation#the-folder-of-a-source) and [OpenFeature providers](/docs/providers/openfeature).
