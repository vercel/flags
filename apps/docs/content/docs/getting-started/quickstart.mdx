This guide connects a flag provider to your application, and imports its flags by name:

```ts
import { enableSale } from 'flags:self';

const sale = await enableSale();
```

Pick your framework in the tabs. The setup is the same in each framework.

<Callout>
  Hono, Express and plain Node.js have no bundler, so they write the source in
  code instead. See [Hono](/docs/frameworks/hono),
  [Express](/docs/frameworks/express) or [no framework](/docs/frameworks/node).
</Callout>

### 1. Install the packages

Install `flags`, the package of your framework, and the OpenFeature provider of your flag management system. This guide uses Vercel Flags, but [any OpenFeature provider](/docs/providers/openfeature) works the same way.

```sh tab="Next.js" title="Terminal"
npm install flags @flags-sdk/next @vercel/flags-core @openfeature/server-sdk
```

```sh tab="SvelteKit" title="Terminal"
npm install flags @flags-sdk/sveltekit @vercel/flags-core @openfeature/server-sdk
```

```sh tab="Nuxt" title="Terminal"
npm install flags @flags-sdk/nuxt @vercel/flags-core @openfeature/server-sdk
```

```sh tab="TanStack Start" title="Terminal"
npm install flags @flags-sdk/tanstack-start @vercel/flags-core @openfeature/server-sdk
```

### 2. Add the plugin

The framework package connects the SDK to the request. With `codeGeneration`, it also turns the folders in `flags/sources` into the imports `flags:<source>`.

```ts tab="Next.js" title="next.config.ts"
import { withFlags } from '@flags-sdk/next/plugin';

export default withFlags(
  {
    // Your Next.js configuration, as usual
  },
  { codeGeneration: true },
);
```

```ts tab="SvelteKit" title="vite.config.ts"
import { flags } from '@flags-sdk/sveltekit/vite';
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [sveltekit(), flags({ codeGeneration: true })],
});
```

```ts tab="Nuxt" title="nuxt.config.ts"
export default defineNuxtConfig({
  modules: [['@flags-sdk/nuxt', { codeGeneration: true }]],
});
```

```ts tab="TanStack Start" title="vite.config.ts"
import { flags } from '@flags-sdk/tanstack-start/vite';
import { tanstackStart } from '@tanstack/react-start/plugin/vite';
import viteReact from '@vitejs/plugin-react';
import { nitro } from 'nitro/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [
    nitro(),
    tanstackStart(),
    viteReact(),
    flags({ codeGeneration: true }),
  ],
});
```

### 3. Create the source `self`

A source is a folder in `flags/sources`. The main source of your application is, by convention, `self`. It has three files:

```txt
flags/
  sources/
    self/
      provider.ts   which provider evaluates the flags
      context.ts    who the user is, for each request
      catalog.ts    which flags exist, for code generation
```

The provider evaluates the flags. It is any OpenFeature server provider:

```ts title="flags/sources/self/provider.ts"
import { VercelProvider } from '@vercel/flags-core/openfeature';

export default new VercelProvider();
```

The context tells the provider who the user is. The SDK calls it once for each request, even when a page evaluates many flags:

```ts title="flags/sources/self/context.ts"
import type { FlagsRequest } from 'flags';

export default function getEvaluationContext(request: FlagsRequest | undefined) {
  return {
    user: { id: request?.cookies?.get('user-id')?.value ?? 'anonymous' },
  };
}
```

The catalog lists the flags of the source. Code generation reads it, and writes one typed import for each flag. Start with a list. Later, you can load it from the API of your flag management system, and keep it in sync while you develop. See [Code generation](/docs/flags/code-generation).

```ts title="flags/sources/self/catalog.ts"
import type { CatalogLoader } from 'flags';

const loadCatalog: CatalogLoader = () => ({
  flags: {
    enableSale: {
      variants: [false, true],
      description: 'Shows the summer sale',
      defaultValue: false,
    },
  },
});

export default loadCatalog;
```

<Callout>
  The provider of Vercel Flags uses the OIDC token of your project. Run `vercel
  link` and `vercel env pull` once. See [Vercel Flags](/docs/providers/vercel).
</Callout>

### 4. Set up TypeScript

The plugin writes the generated modules into `.flags`. Add the folder to `.gitignore`, and tell TypeScript where `flags:self` is:

```txt title=".gitignore"
.flags
```

```json tab="Next.js" title="tsconfig.json"
{
  "compilerOptions": {
    "allowImportingTsExtensions": true,
    "paths": { "flags:*": ["./.flags/*"] }
  }
}
```

```js tab="SvelteKit" title="svelte.config.js"
export default {
  kit: {
    // Also set "allowImportingTsExtensions": true in tsconfig.json
    alias: { 'flags:self': '.flags/self.ts' },
  },
};
```

```txt tab="Nuxt" title="Nothing to do"
The module adds flags:self to the aliases of Nuxt, so its tsconfig has it.
```

```json tab="TanStack Start" title="tsconfig.json"
{
  "compilerOptions": {
    "allowImportingTsExtensions": true,
    "paths": { "flags:*": ["./.flags/*"] }
  }
}
```

### 5. Use the flag

Import the flag, and call it on the server. It returns a promise of its value.

```tsx tab="Next.js" title="app/page.tsx"
import { enableSale } from 'flags:self';

export default async function Page() {
  const sale = await enableSale();
  return <main>{sale ? <p>Summer sale!</p> : null}</main>;
}
```

```ts tab="SvelteKit" title="src/routes/+page.server.ts"
import { enableSale } from 'flags:self';

export async function load() {
  return { sale: await enableSale() };
}
```

```ts tab="Nuxt" title="server/api/sale.get.ts"
import { enableSale } from 'flags:self';

export default defineEventHandler(async () => ({
  sale: await enableSale(),
}));
```

```tsx tab="TanStack Start" title="src/routes/index.tsx"
import { createFileRoute } from '@tanstack/react-router';
import { createServerFn } from '@tanstack/react-start';
import { enableSale } from 'flags:self';

// Flags run on the server, so the loader calls a server function
const getSale = createServerFn({ method: 'GET' }).handler(() => enableSale());

export const Route = createFileRoute('/')({
  loader: () => getSale(),
  component: Home,
});

function Home() {
  const sale = Route.useLoaderData();
  return sale ? <p>Summer sale!</p> : null;
}
```

Start your development server. The plugin generates `.flags/self.ts` before the first request, and again when the catalog changes.

### 6. Optional: decide a flag in code

Not every flag needs a provider. An [inline flag](/docs/flags/inline-flags) decides its value in your code, and gets the same overrides, caching and types. Put inline flags into a module that starts with `'use flags'`:

```ts title="flags.ts"
'use flags';

import { defineFlag } from 'flags';

export const betaBanner = defineFlag({
  key: 'betaBanner',
  decide: (request) => request?.cookies?.get('beta')?.value === '1',
});
```

The `'use flags'` directive lets [Flags Explorer](/docs/tooling/flags-explorer) find these flags. The generated `flags:self` module already has it.

## What happened behind the scenes

`.flags/self.ts` is plain code: one source, and one flag for each key of the catalog. You can write the same code by hand, e.g. in a framework without a bundler:

```ts title=".flags/self.ts (simplified)"
'use flags';

import { bindFlag, defineSource } from 'flags';
import getEvaluationContext from '../flags/sources/self/context.ts';
import provider from '../flags/sources/self/provider.ts';

const source = defineSource({ provider, getEvaluationContext });

export const enableSale = bindFlag({
  key: 'enableSale',
  source,
  options: [false, true],
  defaultValue: false,
});
```

See [Provider flags](/docs/flags/provider-flags) for the API behind it.
