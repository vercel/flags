This guide connects Vercel Flags to your application, and imports its flags by name:

```ts
import { enableSale } from 'flags:self';

const sale = await enableSale();
```

Pick your framework in the tabs. The setup is the same in each framework.

<Callout>
  Hono, Express and plain Node.js have no bundler, so they write the source in
  code instead. See [Hono](/docs/frameworks/hono),
  [Express](/docs/frameworks/express) or [no framework](/docs/frameworks/node).
</Callout>

### 1. Install the packages

Install `flags`, the package of your framework, and the OpenFeature provider of Vercel Flags. For another flag management system, see [Use another provider](#use-another-provider).

```sh tab="Next.js" title="Terminal"
npm install flags @flags-sdk/next @vercel/flags-core @openfeature/server-sdk
```

```sh tab="SvelteKit" title="Terminal"
npm install flags @flags-sdk/sveltekit @vercel/flags-core @openfeature/server-sdk
```

```sh tab="Nuxt" title="Terminal"
npm install flags @flags-sdk/nuxt @vercel/flags-core @openfeature/server-sdk
```

```sh tab="TanStack Start" title="Terminal"
npm install flags @flags-sdk/tanstack-start @vercel/flags-core @openfeature/server-sdk
```

### 2. Add the plugin

The framework package connects the SDK to the request. By default, it also generates the imports `flags:<source>`, e.g. `flags:self` for the flags of your Vercel project.

```ts tab="Next.js" title="next.config.ts"
import { withFlags } from '@flags-sdk/next/plugin';

export default withFlags({
  // Your Next.js configuration, as usual
});
```

```ts tab="SvelteKit" title="vite.config.ts"
import { flags } from '@flags-sdk/sveltekit/vite';
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [sveltekit(), flags()],
});
```

```ts tab="Nuxt" title="nuxt.config.ts"
export default defineNuxtConfig({
  modules: ['@flags-sdk/nuxt'],
});
```

```ts tab="TanStack Start" title="vite.config.ts"
import { flags } from '@flags-sdk/tanstack-start/vite';
import { tanstackStart } from '@tanstack/react-start/plugin/vite';
import viteReact from '@vitejs/plugin-react';
import { nitro } from 'nitro/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [nitro(), tanstackStart(), viteReact(), flags()],
});
```

### 3. Create the flag in Vercel

With `@vercel/flags-core` in your dependencies, your application has the source `self` by default. It has the flags of your Vercel project. You do not create files for it.

Link your application to its Vercel project, and pull its environment variables. The code generation and the provider use the OIDC token of the project:

```sh title="Terminal"
vercel link
vercel env pull
```

Then create a boolean flag `enableSale` in the dashboard of your project, or with the CLI:

```sh title="Terminal"
vercel flags create enableSale --kind boolean
```

See [Vercel Flags](/docs/providers/vercel) for an SDK key instead of the OIDC token.

### 4. Use the flag

Import the flag, and call it on the server. It returns a promise of its value.

```tsx tab="Next.js" title="app/page.tsx"
import { enableSale } from 'flags:self';

export default async function Page() {
  const sale = await enableSale();
  return <main>{sale ? <p>Summer sale!</p> : null}</main>;
}
```

```ts tab="SvelteKit" title="src/routes/+page.server.ts"
import { enableSale } from 'flags:self';

export async function load() {
  return { sale: await enableSale() };
}
```

```ts tab="Nuxt" title="server/api/sale.get.ts"
import { enableSale } from 'flags:self';

export default defineEventHandler(async () => ({
  sale: await enableSale(),
}));
```

```tsx tab="TanStack Start" title="src/routes/index.tsx"
import { createFileRoute } from '@tanstack/react-router';
import { createServerFn } from '@tanstack/react-start';
import { enableSale } from 'flags:self';

// Flags run on the server, so the loader calls a server function
const getSale = createServerFn({ method: 'GET' }).handler(() => enableSale());

export const Route = createFileRoute('/')({
  loader: () => getSale(),
  component: Home,
});

function Home() {
  const sale = Route.useLoaderData();
  return sale ? <p>Summer sale!</p> : null;
}
```

Start your development server. The plugin loads the flags of your Vercel project, and generates `.flags/self.ts` and `flags/generated.d.ts` before the first request. It writes them again when a flag changes in Vercel. You do not need to set up TypeScript.

<Callout>
  If your application has a `src` directory, the types go to
  `src/flags/generated.d.ts`. If the flags can not be loaded, e.g. in CI
  without `vercel env pull`, `flags:self` has no flags and the SDK shows a
  warning. The build does not fail, but the type check fails at the import of
  `enableSale`.
</Callout>

### 5. Optional: add the evaluation context

The evaluation context tells the provider who the user is, e.g. for targeting rules. Add `flags/sources/self/context.ts` (in SvelteKit, `src/flags/sources/self/context.ts`). The SDK calls it once for each request, even when a page evaluates many flags:

```ts title="flags/sources/self/context.ts"
import type { FlagsRequest } from 'flags';

export default function getEvaluationContext(request: FlagsRequest | undefined) {
  return {
    user: { id: request?.cookies?.get('user-id')?.value ?? 'anonymous' },
  };
}
```

Restart the dev server. The source `self` keeps the default provider and catalog of Vercel Flags, and adds your context. In the same way, `provider.ts` or `catalog.ts` in `flags/sources/self` replaces the default provider or catalog. See [The default source `self`](/docs/flags/code-generation#the-default-source-self).

Without `context.ts`, the provider gets only the evaluation context of the call side.

### 6. Optional: decide a flag in code

Not every flag needs a provider. An [inline flag](/docs/flags/inline-flags) decides its value in your code, and gets the same overrides, caching and types. Put inline flags into a module that starts with `'use flags'`:

```ts title="flags.ts"
'use flags';

import { defineFlag } from 'flags';

export const betaBanner = defineFlag({
  key: 'betaBanner',
  decide: (request) => request?.cookies?.get('beta')?.value === '1',
});
```

The `'use flags'` directive lets [Flags Explorer](/docs/tooling/flags-explorer) find these flags. The generated `flags:self` module already has it.

## What happened behind the scenes

`.flags/self.ts` is plain code: one source, and one flag for each flag of your Vercel project. The plugin also writes `flags/generated.d.ts`. It declares the types of `flags:self`, so TypeScript finds them without more setup. You can write the same code by hand, e.g. in a framework without a bundler:

```ts title=".flags/self.ts (simplified)"
'use flags';

import { defineSource } from 'flags';
import getEvaluationContext from '../flags/sources/self/context.ts';
import { VercelProvider } from '@vercel/flags-core/openfeature';

const provider = new VercelProvider();

const source = defineSource({
  provider,
  project: { system: 'vercel-flags', projectId: 'prj_...' },
  getEvaluationContext,
});

export const enableSale = source.bindFlag('enableSale', {
  options: [false, true],
  defaultValue: false,
});
```

The import of `context.ts` is there only if you added the file. See [Provider flags](/docs/flags/provider-flags) for the API behind it.

## Use another provider

With another flag management system, or without `@vercel/flags-core`, create the source yourself. A source is a folder `flags/sources/<source>` with two files, and one optional file:

```txt
flags/
  sources/
    self/
      provider.ts   which provider evaluates the flags
      catalog.ts    which flags exist, for code generation
      context.ts    optional: who the user is, for each request
```

`provider.ts` exports any OpenFeature server provider. `catalog.ts` exports a catalog loader, which returns the flags of the source, e.g. a list in your code. See [Code generation](/docs/flags/code-generation) and [OpenFeature providers](/docs/providers/openfeature).
