---
title: Upgrading from v4
description: What changed in version 5 of the Flags SDK, and how to move your flags.
---

Version 5 turns the Flags SDK from a Next.js and SvelteKit library into a standard for every JavaScript framework, built on OpenFeature. The ideas stay the same: flags as code, evaluated on the server, with overrides from Flags Explorer. The API changed.

## What changed

| v4                                                         | v5                                                                                                   |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `flag({ key, decide })` from `flags/next` or `flags/sveltekit` | `defineFlag({ key, decide })` from `flags`, for an [inline flag](/docs/flags/inline-flags)            |
| `flag({ key, adapter })` with an adapter of `@flags-sdk/*` | `source.bindFlag(key)` on a source of an [OpenFeature provider](/docs/providers)                         |
| `identify` of each flag                                    | `getEvaluationContext` of the source, and of the flag if needed ([evaluation context](/docs/flags/evaluation-context)) |
| `dedupe`                                                    | Built in: each flag and each step of the context runs once per request                              |
| `evaluate` from `flags/next`                               | `evaluate` from `flags`                                                                              |
| Framework-specific imports (`flags/next`, `flags/sveltekit`) | Your code imports only `flags`. Frameworks have a package for the setup: `@flags-sdk/next`, `@flags-sdk/sveltekit`, … |
| `precompute`, `generatePermutations` from `flags/next`     | The same API in [`@flags-sdk/next/precompute`](/docs/frameworks/next/precompute)                      |
| A flag called as `flag(code, group)` on a precomputed page | `getPrecomputed(flag, group, code)`                                                                  |
| `encryptOverrides`, `decryptOverrides`, `encryptFlagValues`, `decryptFlagValues` from `flags` | The same functions from `flags/explorer` |
| `FlagValues` from `flags/react`                            | [`FlagValues`](/docs/frameworks/next/flag-values) from `@flags-sdk/next/flag-values`, encrypted by default |
| The endpoint `/.well-known/vercel/flags` with `getProviderData` | The [flags manifest](/docs/tooling/flags-manifest) of `'use flags'` modules                         |
| Next.js and SvelteKit                                      | Next.js, SvelteKit, Nuxt, TanStack Start, Hono, Express, and [no framework](/docs/frameworks/node)    |

The override cookies of v4, encrypted with `FLAGS_SECRET`, still work. Precompute codes of v4 stay valid if you set `FLAGS_PRECOMPUTE_SECRET` to your `FLAGS_SECRET` during the upgrade.

## Inline flags

A v4 flag with `decide` becomes an inline flag. `decide` now receives the request first and the evaluation context of the call side second, `decide(request, context)`, instead of `{ headers, cookies, entities }`.

```ts tab="v4" title="flags.ts"
import { flag } from 'flags/next';

export const betaBanner = flag<boolean>({
  key: 'betaBanner',
  options: [false, true],
  decide({ cookies }) {
    return cookies.get('beta')?.value === '1';
  },
});
```

```ts tab="v5" title="flags.ts"
'use flags';

import { defineFlag } from 'flags';

export const betaBanner = defineFlag({
  key: 'betaBanner',
  options: [false, true] as const,
  decide: (request) => request?.cookies?.get('beta')?.value === '1',
});
```

## Flags of a provider

In v4, each provider had an adapter. In v5, a provider is an OpenFeature provider, and a source connects it to your flags. `identify` moves to the source, where it runs once per request for all its flags. Each flag of a provider is declared on its source, with `source.bindFlag(key)`. With code generation, the default source `self` of Vercel Flags needs no declaration.

```ts tab="v4" title="flags.ts"
import { flag } from 'flags/next';
import { vercelAdapter } from '@flags-sdk/vercel';

export const summerSale = flag<boolean, { user: { id: string } }>({
  key: 'summerSale',
  adapter: vercelAdapter(),
  identify({ cookies }) {
    return { user: { id: cookies.get('user-id')?.value ?? 'anonymous' } };
  },
});
```

```ts tab="v5" title="flags.ts"
'use flags';

import { defineSource } from 'flags';
import { VercelProvider } from '@vercel/flags-core/openfeature';

const self = defineSource({
  provider: new VercelProvider(),
  project: { system: 'vercel-flags' },
  getEvaluationContext: (request) => ({
    user: { id: request?.cookies?.get('user-id')?.value ?? 'anonymous' },
  }),
});

export const summerSale = self.bindFlag('summerSale');
```

With a framework with a bundler (Next.js, SvelteKit, Nuxt, TanStack Start), you can skip the hand-written code and use the file system API instead: put the provider into `flags/sources/self/provider.ts`, the old `identify` into `flags/sources/self/context.ts`, list the flags in `flags/sources/self/catalog.ts`, and import them with `import { summerSale } from 'flags:self'`. See [Code generation](/docs/flags/code-generation).

For other vendors, use their OpenFeature provider. See [OpenFeature providers](/docs/providers/openfeature).

`@flags-sdk/vercel` and `@flags-sdk/openfeature` are not used with v5. For Vercel Flags, use `VercelProvider` of `@vercel/flags-core/openfeature`, as above. An OpenFeature provider goes directly into `defineSource({ provider })`, so it needs no adapter of `@flags-sdk/openfeature`. Remove both packages when nothing imports them.

The v5 versions of `@flags-sdk/flagsmith`, `@flags-sdk/growthbook`, `@flags-sdk/launchdarkly`, `@flags-sdk/posthog` and `@flags-sdk/statsig` have no adapter. PostHog and Statsig have an OpenFeature provider in `@flags-sdk/posthog/openfeature` and `@flags-sdk/statsig/openfeature`.

## The framework setup

Add the package of your framework, one time. In Next.js:

```ts title="next.config.ts"
import { withFlags } from '@flags-sdk/next/plugin';

export default withFlags({
  // Your Next.js configuration
});
```

See [Frameworks](/docs/frameworks) for the setup of each framework. The Next.js plugin supports Turbopack only.

## Flags Explorer

Remove the route `app/.well-known/vercel/flags/route.ts`. Put your flags into modules that start with `'use flags'`, and add the route of the manifest:

```ts title="app/.well-known/flags/manifest.json/route.ts"
export { GET } from '@flags-sdk/next/manifest';
```

See [Flags Explorer](/docs/tooling/flags-explorer).

## Step by step

1. Install `flags@5` and the package of your framework.
2. Add the framework setup, e.g. `withFlags` in `next.config.ts`.
3. Replace each provider adapter with a source of its OpenFeature provider: a folder `flags/sources/<source>/` with code generation, or `defineSource` by hand.
4. Replace `flag()` with `defineFlag()` for flags with `decide`, and with `source.bindFlag(key)` (or the generated flags of `flags:<source>`) for flags of a provider. Set `type` for each flag that is not a boolean.
5. Move `identify` to `getEvaluationContext(request, input)` of the source, or to the default export of `context.ts`.
6. Add `'use flags'` to your flags modules, and replace the discovery endpoint with the manifest route.
7. Move precompute imports to `@flags-sdk/next/precompute`, and read values with `getPrecomputed`.
8. Run your type check. The types point to the remaining changes.
