Flags SDK is a free, open-source library and an open standard for feature flags in JavaScript.

You define a flag once, in plain TypeScript. You evaluate it on the server in Next.js, SvelteKit, Nuxt, TanStack Start, Hono, Express, or plain Node.js. The value comes from your own code, or from any [OpenFeature](https://openfeature.dev) provider, such as Vercel Flags, LaunchDarkly, flagd or ConfigCat.

```ts title="app/page.tsx"
import { enableSale } from 'flags:self';

const sale = await enableSale();
```

`flags:self` has the flags which you declare in `app.flags`, a [flags file](/docs/flags/flags-files):

```js title="app.flags"
flag enableSale {
  defaultValue: false
}
```

Your code declares which flags exist. Your flag management system decides their values. With Vercel Flags, install `@vercel/flags-core`, and the source `self` needs no other setup. With another provider, a folder in your project names the OpenFeature provider of your flags, and how to find the user of a request:

```txt
flags/sources/self/
  provider.ts   export default new FlagdProvider();
  context.ts    optional: export default (request) => ({ user: getUser(request) });
```

The SDK compiles a flags file into plain code: one source, and one typed flag for each flag. You can also write that code by hand, and decide flags in your own code with inline flags:

```ts title="flags.ts"
'use flags';

import { defineFlag } from 'flags';

export const betaBanner = defineFlag({
  key: 'betaBanner',
  decide: (request) => request?.cookies?.get('beta')?.value === '1',
});
```

## Why a standard

Today, each framework and each flag vendor has its own SDK, with its own way to define a flag, read the request, and cache a value. When you change frameworks or vendors, you rewrite your flags.

Flags SDK separates these concerns:

- **Your flags** are plain code that does not depend on a framework.
- **Providers** follow the [OpenFeature](https://openfeature.dev) standard, so any OpenFeature server provider works without a wrapper.
- **Frameworks** connect the current request to the SDK through a small, written contract: [the standard](/docs/standard). A [conformance suite](/docs/standard/conformance) checks each framework binding.

The result is one primitive for the whole ecosystem. Learn it once, and use it everywhere.

## What you get

- **Two kinds of flags.** [Inline flags](/docs/flags/inline-flags) decide their value in your code. [Provider flags](/docs/flags/provider-flags) ask a provider. Both work the same way.
- **Flags files or hand-written.** Declare your flags in [flags files](/docs/flags/flags-files), and import typed flags from the file or from [`flags:<source>`](/docs/flags/code-generation). Or write `defineSource` and `source.bindFlag` by hand.
- **One value per request.** Each flag is [evaluated once for each request](/docs/flags/evaluating-flags), so all parts of a page see the same value.
- **An evaluation context chain.** The call side, the flag and the source each add a part of the [evaluation context](/docs/flags/evaluation-context), and TypeScript checks each step.
- **OpenFeature compatibility.** Providers, hooks, events and tracking work [as in OpenFeature](/docs/flags/openfeature).
- **Flags Explorer.** Override any flag for your browser from the Vercel Toolbar, with [Flags Explorer](/docs/tooling/flags-explorer).
- **Precompute.** Keep pages static and still show the right variant for each visitor, with [precompute in Next.js](/docs/frameworks/next/precompute).

## Supported frameworks

| Framework      | Package                                                     |
| -------------- | ----------------------------------------------------------- |
| Next.js        | [`@flags-sdk/next`](/docs/frameworks/next)                  |
| SvelteKit      | [`@flags-sdk/sveltekit`](/docs/frameworks/sveltekit)        |
| Nuxt           | [`@flags-sdk/nuxt`](/docs/frameworks/nuxt)                  |
| TanStack Start | [`@flags-sdk/tanstack-start`](/docs/frameworks/tanstack-start) |
| Hono           | [`@flags-sdk/hono`](/docs/frameworks/hono)                  |
| Express        | [`@flags-sdk/express`](/docs/frameworks/express)            |
| No framework   | [`flags` only](/docs/frameworks/node)                       |

Your application code imports only `flags`. The framework package is for the setup, one time.
