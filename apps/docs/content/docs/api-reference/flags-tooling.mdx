These entry points are for framework packages, build tools and other tools,
such as Flags Explorer. Application code does not use them. They are a public
contract: a framework that provides the binding of the Flags SDK itself uses
them in the same way as the `@flags-sdk/*` packages. See
[Custom frameworks](/docs/frameworks/custom-frameworks) and the
[standard](/docs/standard).

## `flags/tooling`

```ts
import {
  addSelfRegistration,
  compileFlagsFile,
  findConfigModules,
  findFlagsFiles,
  findFlagsModules,
  findGeneratedDeclarations,
  formatFlagsFile,
  generateFlags,
  GENERATED_DIRECTORY,
  hasUseFlagsDirective,
  MANIFEST_FILE,
  optionIndex,
  parseFlagsFile,
  readSettings,
  registerFramework,
  renderFlagsFileTypes,
  watchFlags,
  writeFlagsFileDeclaration,
  writeFlagsFileDeclarations,
  writeFlagsFileSources,
  writeManifestFromBuild,
} from 'flags/tooling';
```

### `registerFramework`

```ts
function registerFramework(setup: SetupFramework): void;
```

Registers a framework binding directly, instead of through the alias of
`flags/framework`. Use it when the runtime loads `flags` from `node_modules`,
so that no alias reaches it, e.g. Nitro in development. Call it at startup,
before the first evaluation. The first binding wins, as with the alias.

```ts
import { registerFramework } from 'flags/tooling';
import { setupFramework } from './binding';

registerFramework(setupFramework);
```

### `findConfigModules`

```ts
function findConfigModules(dir: string): Partial<Record<ConfigModule, string>>;
```

Finds the files of the [configuration](/docs/flags/configuration) in the
folder `flags` of `dir`, then of `dir/src`. Returns the path of each file
which exists, by the module that a plugin replaces with it:

| Module            | File                                                    |
| ----------------- | ------------------------------------------------------- |
| `flags/hooks`     | `flags/hooks.ts`, `.mts`, `.js` or `.mjs`               |
| `flags/settings`  | `flags/config.json`                                     |

A plugin sets a bundler alias for each entry. Without a file, it sets no
alias, and `flags` gives an empty default module.

```ts
import { findConfigModules } from 'flags/tooling';

// e.g. { 'flags/hooks': '/app/flags/hooks.ts' }
const aliases = findConfigModules(process.cwd());
```

### `readSettings`

```ts
function readSettings(dir: string): Settings;
```

Reads `flags/config.json` in `dir` or in `dir/src`. Without the file, it
returns the defaults (`{}`). Throws if the file is not valid JSON, has an
unknown key, or has a value of the wrong type. See
[`Settings`](/docs/api-reference/flags#settings).

### `hasUseFlagsDirective`

```ts
function hasUseFlagsDirective(source: string): boolean;
```

Whether the source code of a module starts with the `'use flags'` directive.
It reads only the directive prologue (comments, whitespace and string
literals at the start), as for `'use client'`. It is not a parser.

### `addSelfRegistration`

```ts
function addSelfRegistration(source: string, fileName: string): string;
```

Appends code to a `'use flags'` module that imports the module itself and
passes its exports to `registerFlags` of `flags/runtime`. A build plugin calls it in its
transform step, so nobody has to call `registerFlags` by hand. `fileName` is
the file name of the module, for the self import.

### `findFlagsModules`

```ts
function findFlagsModules(projectDir: string): string[];
```

Returns the paths of all modules with `'use flags'` in the project, relative
to the project with `/`, in a fixed order. Skips `node_modules`, `out`,
`build`, `dist`, `coverage` and hidden directories, except the generated
`.flags` directory.

### `writeManifestFromBuild`

```ts
function writeManifestFromBuild(options: {
  projectDir: string;
  modules: readonly { id: string; file: string }[];
  output: string;
}): Promise<void>;
```

Writes the flags manifest from the built `'use flags'` modules. It imports
them in a child process, so they do not run in the process of the build. `id`
is the path in the project, `file` the built file. Throws with the error
output of the child process if it fails.

### `MANIFEST_FILE`

`'flags-manifest.json'`, the file name of the manifest in the output of a
build.

### `generateFlags`

```ts
function generateFlags(directory?: string): Promise<FlagsAliases>;
```

The function behind `flags sync`. Reads the [flags files](/docs/flags/flags-files)
of the directory, writes the declaration file of each flags file, the module
`.flags/<source>.ts` of each source, `.flags/aliases.json` and
`flags/generated.d.ts`, and returns the aliases, e.g.
`{ 'flags:self': './.flags/self.ts' }`. The default directory is the current
directory. It uses no network. A key or a name in two files of one source
makes it reject. Without flags files, it writes nothing, and removes the
modules of an earlier run. See [Code generation](/docs/flags/code-generation).

### `watchFlags`

```ts
function watchFlags(
  directory: string,
  options: { signal: AbortSignal },
): Promise<WatchResult>;
```

The function behind `flags watch`. Writes the same files as `generateFlags`,
and again after each change of a flags file or of a folder of a source, until
the signal aborts. A conflict is an error on the console, and the watch goes
on. Resolves when the first modules exist, with `WatchResult`:

- `aliases: FlagsAliases`: the aliases after the first write.
- `done: Promise<void>`: resolves when the signal aborts.

### `writeFlagsFileSources`

```ts
function writeFlagsFileSources(directory: string): Promise<FlagsFileSourcesResult>;
```

Writes only the modules of `flags:<source>`, `.flags/aliases.json` and
`flags/generated.d.ts`. The module of a source re-exports the flags of that
source from all flags files, e.g.
`export { checkout, summerSale } from '../app.flags';`. A flags file without
flags still defines its source. It removes the module of a source which no
flags file has any more. Returns `{ aliases, conflicts }`: `conflicts` lists
the flags with a key or a name of another file of the same source. They are
not in `flags:<source>`.

### `findGeneratedDeclarations`

```ts
function findGeneratedDeclarations(directory: string): Promise<string | undefined>;
```

Finds `flags/generated.d.ts`, the types of `flags:<source>`, in the directory
or in its `src` directory. Returns the absolute path, or `undefined` if the
code generation did not write the file. Use it instead of
`findFlagsDirectory`, since the types can be in a folder `flags` without
`flags/sources`. The Nuxt module uses it to add the types to Nuxt.

### `findFlagsFiles`

```ts
function findFlagsFiles(projectDir: string): string[];
```

The paths of the flags files (`*.flags`) of the project, relative to the
project and with `/`, in a fixed order.

### `compileFlagsFile`

```ts
function compileFlagsFile(text: string, options: CompileOptions): CompiledFlagsFile;
```

Compiles a flags file into a `'use flags'` module: the imports of
`provider.ts`, `context.ts` and `hooks.ts` of each source, one `defineSource`
for each source of the flags of the file, and one `source.bindFlag` for each
flag, exported under its name. For the source `self` of an application which
depends on `@vercel/flags-core`, without `provider.ts`, the module creates
`new VercelProvider()`. Throws a `FlagsFileError` with the position of each
error. The framework loaders use it.

- `CompileOptions`: `{ fileName: string; projectDirectory?: string; selfRegistration?: boolean }`.
  `projectDirectory` is the directory with `flags/sources`. The default is the
  nearest directory of the file with a `package.json`. `selfRegistration`
  adds `registerFlags` at the end of the module. The default is `true`.
- `CompiledFlagsFile`: `{ code, document, sources, ... }`. `code` is
  JavaScript, which is also valid TypeScript.

### `renderFlagsFileTypes`

```ts
function renderFlagsFileTypes(
  text: string,
  options: { fileName: string; projectDirectory?: string },
): FlagsFileTypes;
```

The types of a flags file: one declaration for each flag, with the type that
`source.bindFlag` gives in hand-written code. It never throws: a flag with an
error is left out, and the diagnostics say why.

### `writeFlagsFileDeclaration` and `writeFlagsFileDeclarations`

```ts
function writeFlagsFileDeclaration(file: string, text: string, projectDirectory: string): boolean;
function writeFlagsFileDeclarations(projectDirectory: string): Promise<FlagsFileDeclarationsResult>;
```

`writeFlagsFileDeclaration` writes the declaration file of one flags file,
e.g. `app.d.flags.ts` for `app.flags`, if it changed, and returns whether it
wrote the file. The framework loaders call it when they compile a file.
`writeFlagsFileDeclarations` writes the declaration file of each flags file
of the project, and removes the declaration files of removed flags files. It
returns `{ files, problems }`. `watchFlagsFileDeclarations(projectDirectory, signal)`
writes them again after each change.

### `parseFlagsFile` and `formatFlagsFile`

```ts
function parseFlagsFile(text: string): FlagsFileDocument;
function formatFlagsFile(text: string, options?: { fileName?: string }): string;
```

`parseFlagsFile` reads a flags file. It never throws: an error is a
diagnostic with its position, and a flag with an error is not in `flags`.
`formatFlagsFile` formats a flags file, as `flags format` does. It throws a
`FlagsFileError` if the file has a syntax error.

### `GENERATED_DIRECTORY`

`'.flags'`, the directory of the generated modules. It also contains
`aliases.json`, which framework plugins read to point `flags:<source>` to the
modules.

### `optionIndex`

```ts
function optionIndex(value: unknown, options: readonly FlagOptionObject<FlagValue>[]): number;
```

The index of the option with this value, or `-1`. Compares JSON values by
their content. Precompute uses it to encode values.

### Types

- `FlagsAliases`: `Record<string, string>`, e.g.
  `{ 'flags:self': './.flags/self.ts' }`, relative to the application.
- `WatchResult`: the result of `watchFlags`.
- `ConfigModule`: `'flags/hooks' | 'flags/settings'`,
  the modules which a plugin replaces with the files of the configuration.
- `FlagsFileSourcesResult`: the result of `writeFlagsFileSources`.
- `FlagsFileDeclarationsResult`: the result of `writeFlagsFileDeclarations`.
- `FlagsFileDocument`, `FlagsFileFlag`, `FlagsFileDiagnostic`: the result of
  `parseFlagsFile`.

## `flags/manifest`

Creates, checks and reads the flags manifest: the list of flags of an
application, which Flags Explorer reads. See
[Flags manifest](/docs/tooling/flags-manifest) and the
[manifest format](/docs/standard/flags-manifest-format).

```ts
import {
  createManifest,
  expandTemplate,
  resolveFlagLinks,
  validateFlagsManifest,
  validateSystemManifest,
} from 'flags/manifest';
```

### `createManifest`

```ts
function createManifest(modules: readonly FlagsModule[]): FlagsManifest;
```

Creates the manifest from the exports of the `'use flags'` modules. It does not
evaluate flags.

Throws if an export is not a flag, or if two exports declare the same key with
different values.

```ts
import { createManifest } from 'flags/manifest';

const manifest = createManifest([
  { id: 'flags.ts', exports: { ...(await import('./flags')) } },
]);
```

### `validateFlagsManifest`

```ts
function validateFlagsManifest(value: unknown): FlagsManifest;
```

Checks a manifest, e.g. after a tool reads `flags-manifest.json`. Throws a
`TypeError` if it does not follow version 1 of the format
(`https://flags-sdk.dev/schemas/flags-manifest.v1.json`). Unknown fields are
allowed.

### `validateSystemManifest`

```ts
function validateSystemManifest(value: unknown): SystemManifest;
```

Checks a system manifest, e.g. after a fetch: version 1, a `name`, and `links`
that are HTTPS URLs without a placeholder in their origin. Throws a
`TypeError` if it is not valid.

### `resolveFlagLinks`

```ts
function resolveFlagLinks(
  systemManifest: SystemManifest,
  variables: Readonly<Record<string, string>>,
  flagKey: string,
): FlagLinks;
```

Builds the links of a flag to the dashboard of its system, from the system
manifest and the `variables` of the flag's source in the flags manifest. A
link whose variables are not all known is left out.

### `expandTemplate`

```ts
function expandTemplate(template: string, values: Readonly<Record<string, string>>): string | undefined;
```

Replaces the `{name}` placeholders of a URL template (RFC 6570 level 1) with
URL-encoded values. Returns `undefined` if a value is missing, so a tool shows
no link instead of a broken one.

### Types

| Type                     | Description                                                                                                                 |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `FlagsModule`            | `{ id: string; exports: Record<string, unknown> }`: a `'use flags'` module and its exports.                                  |
| `FlagsManifest`          | `{ version: 1; sources: Record<string, FlagManifestSource>; definitions: Record<string, FlagManifestDefinition> }`        |
| `FlagManifestDefinition` | `type`, `options?`, `defaultValue?`, `description?`, `declaredInCode: true`, `source?` (an id in `sources`), `declarations` |
| `FlagManifestSource`     | `{ system: string; systemManifest?: string; variables: Record<string, string> }`. Variables are public identifiers, never credentials. |
| `FlagDeclaration`        | `{ module: string; export: string }`: where a flag is declared.                                                             |
| `SystemManifest`         | `{ version: 1; name: string; logo?: string; variables?: Record<string, { description?: string }>; links: SystemManifestLinks }` |
| `SystemManifestLinks`    | `{ flag?: string; createFlag?: string; project?: string }`: URL templates. `flag` has the variable `flagKey`.               |
| `FlagLinks`              | `{ flag?: string; createFlag?: string; project?: string }`: resolved URLs.                                                  |

## The CLI

The `flags` package has a `flags` command.

```sh
flags manifest [dir] [--out <file>]
flags sync [dir]
flags watch [dir] [-- command ...args]
flags format [paths...] [--check]
flags format --stdin [--stdin-filepath <file>]
```

See [CLI](/docs/tooling/cli) for a guide.

### `flags sync`

Writes the modules of `flags:<source>` and the types of the flags files once:
`.flags/<source>.ts`, `flags/generated.d.ts` and the `*.d.flags.ts` files. It
reads only the flags files, and uses no network. A key or a name in two files
of one source makes it fail.

| Argument | Description                                                             |
| -------- | ----------------------------------------------------------------------- |
| `dir`    | The directory of the application. The default is the current directory. |

```sh
flags sync
```

### `flags watch`

Like `flags sync`, and writes the modules and the types again after each
change of a flags file. With `-- command`, it starts the command after the first modules
exist, e.g. a development server, and stops when the command ends.

```sh
flags watch -- vite dev
```

### `flags format`

Formats the flags files in place: the files which you give, and the flags
files of the folders. The default is the current directory. `--check` writes
nothing, and fails if a file is not formatted. `--stdin` formats the standard
input to the standard output, for editors. `--stdin-filepath` gives the name
of the file for the error messages.

```sh
flags format --check
```

### `flags manifest`

Writes the flags manifest for applications without a framework plugin, e.g.
Hono or Express on Node.js. It imports the `'use flags'` modules in `dir`
with Node.js, loads `flags/hooks.ts` and `flags/config.json` if it finds
them (in `dir` or its `src`), and writes the
manifest.

| Argument       | Description                                                                 |
| -------------- | --------------------------------------------------------------------------- |
| `dir`          | The directory to search. The default is the current directory.              |
| `--out <file>` | The output file. The default is `flags-manifest.json` in `dir`.             |

Run it after the build, on the output of the build, or on the source if
Node.js can run it, e.g. TypeScript with type stripping.

```sh
flags manifest dist
```
