The `flags` package has a command line tool, `flags`. You do not install anything else:

```bash
npx flags sync
```

| Command | What it does |
| --- | --- |
| [`flags sync`](#flags-sync) | Writes the modules of `flags:<source>` and the types of your [flags files](/docs/flags/flags-files) one time. |
| [`flags watch`](#flags-watch) | Writes them again after each change of a flags file, and can start your development server. |
| [`flags format`](#flags-format) | Formats your flags files. |
| [`flags manifest`](#flags-manifest) | Writes the [flags manifest](/docs/tooling/flags-manifest) of an application without a framework plugin. |

With a framework plugin, the code generation runs for you by default, during the build and in development: `withFlags` for Next.js, `flags()` of `@flags-sdk/sveltekit/vite` or `@flags-sdk/tanstack-start/vite`, and the module `@flags-sdk/nuxt` for Nuxt. You need `flags sync` and `flags watch` for frameworks without a bundler, e.g. Hono, Express or plain Node.js, and for CI steps which run before the build, e.g. the type check.

## `flags sync`

```bash
flags sync [dir]
```

Reads the flags files of your application one time, and writes:

- `.flags/<source>.ts` for each source of the flags files, e.g. `.flags/self.ts` for `flags:self`, and `.flags/aliases.json` for the framework plugins;
- the types of `flags:<source>` in `flags/generated.d.ts`. The folder `flags` is in `dir` or in its `src` folder;
- a declaration file next to each flags file, e.g. `app.d.flags.ts` for `app.flags`.

See [Code generation](/docs/flags/code-generation).

- `dir` is the directory of your application. The default is the current directory.
- It reads only the flags files. It uses no network and no credentials, so it works offline and in CI.
- A key or a name in two files of one source is a conflict, and the command fails.
- It writes a file only when its content changes, and removes the module of a source which no flags file has any more.
- Without flags files, it writes nothing.

Run it before the type check, e.g. in CI:

```json title="package.json"
{
  "scripts": {
    "type-check": "flags sync && tsc --noEmit"
  }
}
```

## `flags watch`

```bash
flags watch [dir] [-- command ...args]
```

Writes the same files as `flags sync`, then writes them again after each change of a flags file.

- With `-- command`, it starts the command after the first write, and stops when the command ends. Use it to run your development server with up-to-date types:

  ```json title="package.json"
  {
    "scripts": {
      "dev": "flags watch -- node --import flags/register --watch server.ts"
    }
  }
  ```

- A conflict is an error on the console. The command does not stop.
- It stops on `SIGINT` and `SIGTERM`.
- A flags file with a new source needs a restart.

## `flags format`

```bash
flags format [paths...] [--check]
flags format --stdin [--stdin-filepath <file>]
```

Formats the flags files in place: the files which you give, and the flags files of the folders. The default is the current directory. See [Format](/docs/flags/flags-files#format).

- `--check` writes nothing, and fails if a file is not formatted, e.g. in CI.
- `--stdin` formats the standard input to the standard output, for editors. `--stdin-filepath` gives the name of the file for the error messages.
- A file with a syntax error is not formatted, and the command shows the error.

## `flags manifest`

```bash
flags manifest [dir] [--out <file>]
```

Writes the flags manifest for applications without a framework plugin, e.g. Hono or Express on Node.js. Framework plugins of Next.js, SvelteKit, Nuxt and TanStack Start write the manifest themselves.

- It finds the modules which start with `'use flags'` in `dir` (the default is the current directory), imports them with Node.js, and writes the manifest. It skips `node_modules`, build outputs and hidden directories, except `.flags`.
- It loads `flags/hooks.ts` and `flags/config.json` if it finds them in `dir` or in its `src` directory.
- `--out` sets the file. The default is `flags-manifest.json` in `dir`.

Run it on the output of `tsc`, which keeps the `'use flags'` directive, or on your TypeScript source if Node.js can run it (type stripping, Node.js 22.18 or newer). A bundled output loses the directive.

```json title="package.json"
{
  "scripts": {
    "build": "tsc",
    "postbuild": "flags manifest dist"
  }
}
```
