The `flags` package has a command line tool, `flags`. You do not install anything else:

```bash
npx flags sync
```

| Command | What it does |
| --- | --- |
| [`flags sync`](#flags-sync) | Generates the modules of `flags:<source>` one time, from the catalogs in `flags/sources` and of the default source `self`. |
| [`flags watch`](#flags-watch) | Generates them again after each change of a catalog, and can start your development server. |
| [`flags manifest`](#flags-manifest) | Writes the [flags manifest](/docs/tooling/flags-manifest) of an application without a framework plugin. |

With a framework plugin, the code generation runs for you by default, during the build and in development: `withFlags` for Next.js, `flags()` of `@flags-sdk/sveltekit/vite` or `@flags-sdk/tanstack-start/vite`, and the module `@flags-sdk/nuxt` for Nuxt. You need `flags sync` and `flags watch` for frameworks without a bundler, e.g. Hono, Express or plain Node.js, and for CI steps which run before the build, e.g. the type check.

## `flags sync`

```bash
flags sync [dir] [--production] [--disable-self-source]
```

Runs the catalog of each source in `flags/sources/<source>` one time, and writes `.flags/<source>.ts`, e.g. `.flags/self.ts` for the main source `flags/sources/self`. It also writes the types of `flags:<source>` into `flags/generated.d.ts`. The folder `flags` is in `dir` or in its `src` folder. See [Code generation](/docs/flags/code-generation).

If your application depends on `@vercel/flags-core`, it also writes the [default source `self`](/docs/flags/code-generation#the-default-source-self) with the flags of your Vercel project, also without `flags/sources/self`. If these flags can not be loaded, e.g. without `vercel env pull`, `flags:self` has no flags, the command warns, and it does not fail.

- `dir` is the directory of your application. The default is the current directory.
- `--production` loads the `.env` files for production. See [Environment variables](#environment-variables).
- `--disable-self-source` turns off the default source `self`. The command then makes no requests to Vercel Flags for it.
- It writes a file only when its content changes, and removes the module of a removed source.
- If a catalog fails, the command fails, and the last generated modules stay.

Run it before the type check and the build, e.g. in CI:

```json title="package.json"
{
  "scripts": {
    "type-check": "flags sync && tsc --noEmit",
    "build": "flags sync && vite build"
  }
}
```

## `flags watch`

```bash
flags watch [dir] [--production] [--disable-self-source] [-- command ...args]
```

Generates the modules, then generates them again each time a catalog yields a new catalog, e.g. when someone changes a flag in the dashboard. It takes the same options as `flags sync`.

- With `-- command`, it starts the command after the first generation, and stops when the command ends. Use it to run your development server with up-to-date flags:

  ```json title="package.json"
  {
    "scripts": {
      "dev": "flags watch -- vite dev"
    }
  }
  ```

- It stops on `SIGINT` and `SIGTERM`.
- A change of `provider.ts`, `context.ts` or `catalog.ts` needs a restart.

## Environment variables

`flags sync` and `flags watch` load the `.env` files of the directory first, so that catalogs have their credentials, e.g. the OIDC token of `vercel env pull`. The order:

1. `.env.<mode>.local`
2. `.env.local`
3. `.env.<mode>`
4. `.env`

An earlier file wins, and a variable which is set already wins over all files. The mode is `production` with `--production` or with `NODE_ENV=production`, and `development` otherwise.

## `flags manifest`

```bash
flags manifest [dir] [--out <file>]
```

Writes the flags manifest for applications without a framework plugin, e.g. Hono or Express on Node.js. Framework plugins of Next.js, SvelteKit, Nuxt and TanStack Start write the manifest themselves.

- It finds the modules which start with `'use flags'` in `dir` (the default is the current directory), imports them with Node.js, and writes the manifest. It skips `node_modules`, build outputs and hidden directories, except `.flags`.
- It loads `flags/config.ts` if it finds one in `dir`, in its `src` directory, or in the current directory.
- `--out` sets the file. The default is `flags-manifest.json` in `dir`.

Run it on the output of `tsc`, which keeps the `'use flags'` directive, or on your TypeScript source if Node.js can run it (type stripping, Node.js 22.18 or newer). A bundled output loses the directive.

```json title="package.json"
{
  "scripts": {
    "build": "tsc",
    "postbuild": "flags manifest dist"
  }
}
```
