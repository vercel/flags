[Vercel Flags](https://vercel.com/docs/flags/vercel-flags) is the feature flag platform built into Vercel. You manage flags in the dashboard of your Vercel project, and your application evaluates them on the server, without a network request for each flag.

The Flags SDK uses Vercel Flags through `VercelProvider`, the OpenFeature server provider of `@vercel/flags-core`. There is no separate adapter: `VercelProvider` is a regular OpenFeature provider, so everything on this page works the same way as with any other [provider](/docs/providers).

## Quickstart

This quickstart assumes that your framework is set up already, e.g. with `withFlags` in `next.config.ts`. See [Frameworks](/docs/frameworks) for your framework.

### 1. Install the packages

```bash
npm install flags @vercel/flags-core @openfeature/server-sdk
```

`@openfeature/server-sdk` is a peer dependency of `VercelProvider`, as for most OpenFeature providers. Your code does not import it.

### 2. Create a flag in Vercel

Create a boolean flag called `summer-sale` in the dashboard of your project:

<LearnMore icon="arrow" target="_blank" href="https://vercel.com/d?to=%2F%5Bteam%5D%2F%5Bproject%5D%2Fflags%3Fcreate%3D1&title=Go+to+Vercel+Flags">
  Create a flag
</LearnMore>

### 3. Pull the environment variables

`VercelProvider` authenticates with the OpenID Connect (OIDC) token of your Vercel project. Deployments on Vercel receive the token automatically. For local development, link the project and pull the environment variables into `.env.local`:

```bash
vercel link
vercel env pull
```

### 4. Make Vercel Flags the default source

```ts title="flags.config.ts"
import { VercelProvider } from '@vercel/flags-core/openfeature';
import { defineConfig, defineSource } from 'flags';

export const config = defineConfig({
  defaultSource: defineSource({
    provider: new VercelProvider(),
    // The flags of the Vercel project of this deployment
    project: { system: 'vercel-flags' },
    // The entities which your targeting rules use, once per request
    getEvaluationContext: (_input, request) => ({
      user: { id: request?.cookies?.get('user-id')?.value ?? 'anonymous' },
    }),
  }),
});

// Gives flags without a source the types of this source
declare module 'flags' {
  interface Register {
    config: typeof config;
  }
}
```

### 5. Declare and evaluate the flag

```ts title="flags.ts"
'use flags';

import { bindFlag } from 'flags';

export const summerSale = bindFlag({
  key: 'summer-sale',
  defaultValue: false,
  description: 'Shows the summer sale banner',
});
```

```tsx title="app/page.tsx"
import { summerSale } from '../flags';

export default async function Page() {
  const sale = await summerSale();
  return <div>{sale ? 'Summer sale!' : 'Welcome'}</div>;
}
```

Toggle the flag for the development environment in the dashboard, and reload the page.

## Targeting

`VercelProvider` evaluates your targeting rules against the evaluation context which `getEvaluationContext` returns. Return the entities which your rules use, e.g. the user and the team:

```ts title="flags.config.ts"
getEvaluationContext: async (_input, request) => {
  const session = await getSession(request?.cookies);
  return {
    user: { id: session.userId },
    team: { id: session.teamId },
  };
},
```

The source runs `getEvaluationContext` once per request, so a session lookup happens once, also when a page evaluates many flags. Keep it fast: read cookies and headers, and avoid network requests where you can. See [Evaluation context](/docs/flags/evaluation-context).

Configure which entities your project can target in the dashboard:

<LearnMore icon="arrow" target="_blank" href="https://vercel.com/d?to=%2F%5Bteam%5D%2F%5Bproject%5D%2Fflags%2F%5Bentities&title=Go+to+Vercel+Flags">

</LearnMore>

## Configure the client

`new VercelProvider()` uses the default client of `@vercel/flags-core`. It uses the SDK key in the `FLAGS` environment variable if you set one, and the OIDC token of the project otherwise. To configure the client, pass an SDK key or a client:

```ts title="sources.ts"
import { createClient } from '@vercel/flags-core';
import { VercelProvider } from '@vercel/flags-core/openfeature';

// An SDK key, e.g. for an application outside Vercel
const withKey = new VercelProvider(process.env.CUSTOM_FLAGS_KEY!);

// A client with options
const withClient = new VercelProvider(
  createClient({ clientName: 'my-app' }),
);
```

## The flags of a different project

A source can read the flags of a different Vercel project. Set `projectId` (and `teamId` for a project of a different team) in `project`, so that Flags Explorer links to the right project, and give the provider access to that project:

```ts title="sources.ts"
import { createClient } from '@vercel/flags-core';
import { VercelProvider } from '@vercel/flags-core/openfeature';
import { defineSource } from 'flags';

// A project of the same team, through a Project Connection
export const shared = defineSource({
  provider: new VercelProvider(createClient({ projectId: 'prj_source' })),
  project: { system: 'vercel-flags', projectId: 'prj_source' },
});

// A project of a different team, with an SDK key of that project
export const blog = defineSource({
  provider: new VercelProvider(process.env.BLOG_FLAGS!),
  project: { system: 'vercel-flags', projectId: 'prj_blog', teamId: 'team_acme' },
});
```

```ts title="flags.ts"
'use flags';

import { bindFlag } from 'flags';
import { blog } from './sources';

export const newSearch = bindFlag({ key: 'new-search', source: blog });
```

- **Project Connections** let a project read the flags of another project of the same team, with its own OIDC token. Grant access in the **Flags → Connections** page of the source project. See [Project Connections](https://vercel.com/docs/flags/vercel-flags/project-connections).
- **SDK keys** work for any project. The SDK key must belong to the project in `project`: the SDK cannot check this, because OpenFeature providers do not report their project.

## Code generation

With [code generation](/docs/flags/code-generation), you do not declare each flag by hand. A catalog reads the flags of your Vercel project, and the SDK generates one typed `bindFlag` for each flag, with its variants as options and its description as JSDoc.

Each source is a directory in `flags/sources`. For a source named `site`:

```ts title="flags/sources/site/provider.ts"
import { createClient } from '@vercel/flags-core';
import { VercelProvider } from '@vercel/flags-core/openfeature';

// The OpenFeature provider of the source. Without an SDK key, the client
// uses the OIDC token of the project, e.g. after vercel env pull.
export default new VercelProvider(createClient({ clientName: 'my-app' }));
```

```ts title="flags/sources/site/context.ts"
import type { FlagsRequest } from 'flags';

// The evaluation context of all flags of this source, once per request
export default function getEvaluationContext(
  _input: unknown,
  request: FlagsRequest | undefined,
) {
  return {
    user: { id: request?.cookies?.get('user-id')?.value ?? 'anonymous' },
  };
}
```

```ts title="flags/sources/site/catalog.ts"
import type { DatafileInput } from '@vercel/flags-core';
import type { Catalog, CatalogLoadOptions } from 'flags';
import { streamDatafiles } from './stream.ts';

function catalogFromDatafile(datafile: DatafileInput): Catalog {
  if (!datafile.projectId || !datafile.environment || !datafile.definitions) {
    throw new Error('The provider returned an invalid flags datafile.');
  }

  const flags = Object.fromEntries(
    Object.entries(datafile.definitions).map(([key, definition]) => [
      key,
      { variants: definition.variants },
    ]),
  );

  return {
    // For the links of Flags Explorer
    project: { system: 'vercel-flags', projectId: datafile.projectId },
    revision: datafile.revision,
    flags,
  };
}

// Yields a new catalog after each change in Vercel, so that
// `next dev` and `flags watch` update the generated code
export default async function* loadCatalog({
  signal,
}: CatalogLoadOptions): AsyncGenerator<Catalog> {
  for await (const datafile of streamDatafiles({ signal })) {
    yield catalogFromDatafile(datafile);
  }
}
```

`stream.ts` subscribes to the changes of the flags of your project. Copy it from the [playground of the Flags SDK repository](https://github.com/vercel/flags/tree/main/apps/playground/flags/sources/site), which runs this setup against real Vercel Flags. The catalog runs only during code generation, in Node.js, not in your application.

Then enable code generation, and import the flags of the source by its name:

```ts title="next.config.ts"
import { withFlags } from '@flags-sdk/next/plugin';

export default withFlags({}, { codeGeneration: true });
```

```tsx title="app/page.tsx"
import { 'summer-sale' as summerSale } from 'flags:site';

export default async function Page() {
  const sale = await summerSale();
  return <div>{sale ? 'Summer sale!' : 'Welcome'}</div>;
}
```

See [Code generation](/docs/flags/code-generation) for the `tsconfig.json` paths, the `.gitignore` entry, and the `flags sync` and `flags watch` commands for other frameworks.

## Flags Explorer

[Flags Explorer](/docs/tooling/flags-explorer) in the Vercel Toolbar works with Vercel Flags without extra setup:

- **Overrides.** Flags Explorer sets an override cookie which Vercel signs. The SDK verifies it with the public keys of Vercel: on Vercel, and locally after `vercel env pull`. You do not need a `FLAGS_SECRET`. See [Overrides](/docs/tooling/overrides).
- **Dashboard links.** With `project: { system: 'vercel-flags' }`, Flags Explorer links each flag to its page in the dashboard.
- **Reporting.** `VercelProvider` reports each evaluation to Vercel, and reports overrides with a hook, so that you can see the values of your flags in Vercel.

## The default provider of a deployment

The SDK resolves flags without a source through the module `flags/default-provider`. A deployment platform can replace this module at build time with a bundler alias, so that flags without a source use a fast provider of the platform without any configuration.

`@vercel/flags-core/default-provider` is this module for Vercel. It exports `createDefaultProvider()`, which returns a `VercelProvider` with the default client. A deployment adapter, e.g. of Next.js on Vercel, can point `flags/default-provider` to it for production builds.

- A `defaultSource` in `flags.config.ts` always wins over the provider of the platform.
- The platform replaces the module only for builds, not for development.
- Until your platform does this, set a `defaultSource` in `flags.config.ts`, as in the [quickstart](#4-make-vercel-flags-the-default-source).

See [Framework bindings](/docs/standard/framework-bindings#the-replaceable-modules) for the contract.
