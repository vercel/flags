Any [OpenFeature](https://openfeature.dev/) server provider works with the Flags SDK, as it is. This page lists providers which we know, with the package to install and a `defineSource` snippet for each. For providers which are not on this page, see the [OpenFeature ecosystem](https://openfeature.dev/ecosystem) (filter for server-side JavaScript providers).

<Callout>
The setup of each provider is a short summary of the documentation of the vendor. Options and package names can change. Check the documentation of the provider, linked in each section, for the options which you need in production.
</Callout>

## How to use a provider

The setup is the same for each provider. With a framework with a bundler (Next.js, SvelteKit, Nuxt, TanStack Start), use [flags files](/docs/flags/flags-files): the provider goes into the folder of a source, and a flags file declares the flags. By convention, the main source of an app is `self`. Hono, Express and plain Node.js can use flags files too, with `node --import flags/register`.

### 1. Install the packages

Install `flags`, `@openfeature/server-sdk` (the peer dependency of most OpenFeature providers), and the provider:

```bash
npm install flags @openfeature/server-sdk @openfeature/flagd-provider
```

### 2. Export the provider

The default export of `provider.ts` is the provider:

```ts title="flags/sources/self/provider.ts"
import { FlagdProvider } from '@openfeature/flagd-provider';

export default new FlagdProvider();
```

### 3. Create the evaluation context

Most OpenFeature providers identify the user by the `targetingKey` of the evaluation context. The default export of `context.ts` creates it once per request:

```ts title="flags/sources/self/context.ts"
import type { FlagsRequest } from 'flags';

export default function getEvaluationContext(
  request: FlagsRequest | undefined,
) {
  return {
    targetingKey: request?.cookies?.get('user-id')?.value ?? 'anonymous',
  };
}
```

The SDK gives no field a special meaning. Return what your provider needs, e.g. more attributes for its targeting rules. See [Evaluation context](/docs/flags/evaluation-context).

### 4. Declare the flags

Declare the flags of the source in `app.flags`, with the keys of your flag management system:

```js title="app.flags"
flag checkout {
  description: "The checkout flow"
  options: ["control", "express"]
  defaultValue: "control"
}
```

See [Flags files](/docs/flags/flags-files) for the format.

### 5. Import the flags

After you add the plugin of your framework (see [Code generation](/docs/flags/code-generation#2-add-the-plugin)), import the flags from `flags:self`, or from `./app.flags`:

```ts
import { checkout } from 'flags:self';

const variant = await checkout();
```

### Without flags files

If you prefer to write the code, define the source and the flags by hand. The provider snippets below use this form:

```ts title="flags/context.ts"
import type { FlagsRequest } from 'flags';

export function getEvaluationContext(request: FlagsRequest | undefined) {
  return {
    targetingKey: request?.cookies?.get('user-id')?.value ?? 'anonymous',
  };
}
```

```ts title="flags/self.ts"
import { FlagdProvider } from '@openfeature/flagd-provider';
import { defineSource } from 'flags';
import { getEvaluationContext } from './context';

export const self = defineSource({
  provider: new FlagdProvider(),
  getEvaluationContext,
});
```

Declare each flag on the source, with `self.bindFlag(key)`:

```ts title="flags.ts"
'use flags';

import { self } from './flags/self';

export const checkout = self.bindFlag('checkout', {
  type: 'string',
  options: ['control', 'express'],
  defaultValue: 'control',
});
```

With flags files, take the `provider` of a snippet below as the default export of `flags/sources/self/provider.ts`.

Do not call `OpenFeature.setProvider()`: the SDK calls the provider directly, and initializes it before the first evaluation. See [Providers](/docs/providers) for the lifecycle, and [OpenFeature compatibility](/docs/flags/openfeature) for hooks, events and tracking.

<Callout title="Providers which connect when you create them">
Tools import your `'use flags'` modules to read your flags, so creating a source must not open network connections. Most providers connect in `initialize()`. If a provider connects in its constructor or factory (below: CloudBees and Split), it also connects when a tool imports your flags, e.g. when a build writes the flags manifest. Create such a provider once, in a module of its own like `flags/sources/self/provider.ts` or `flags/self.ts`, and check the documentation of the provider for a lazy option.
</Callout>

## Providers of the Flags SDK

These providers are part of the Flags SDK. The Flags SDK team maintains them.

### PostHog

```bash
npm install flags @openfeature/server-sdk posthog-node @flags-sdk/posthog
```

```ts title="flags/self.ts"
import { PostHogProvider } from '@flags-sdk/posthog/openfeature';
import { defineSource } from 'flags';
import { PostHog } from 'posthog-node';
import { getEvaluationContext } from './context';

export const posthog = defineSource({
  provider: new PostHogProvider(
    new PostHog(process.env.POSTHOG_PROJECT_API_KEY!, {
      host: process.env.POSTHOG_HOST,
    }),
  ),
  getEvaluationContext,
});
```

The `targetingKey` of the evaluation context is the distinct ID. A boolean flag reads whether the flag is enabled, a string flag reads the variant key of a multivariate flag, and number and object flags read the JSON payload.

[PostHog provider documentation](https://github.com/vercel/flags/tree/main/packages/adapter-posthog#openfeature-provider)

### Statsig

```bash
npm install flags @openfeature/server-sdk @statsig/statsig-node-core @flags-sdk/statsig
```

```ts title="flags/self.ts"
import { StatsigProvider } from '@flags-sdk/statsig/openfeature';
import { defineSource } from 'flags';
import { getEvaluationContext } from './context';

export const statsig = defineSource({
  // Creates a Statsig instance of the Statsig Server Core SDK. It fetches
  // the rules on initialization, not at import.
  provider: new StatsigProvider(process.env.STATSIG_SERVER_API_KEY!),
  getEvaluationContext,
});
```

The flag key selects the Statsig entity. A plain key, e.g. `showBanner`, is a feature gate. The prefixes `config:`, `experiment:` and `layer:` select a dynamic config, an experiment or a layer, e.g. `config:welcome`. Without a parameter, an object flag reads the whole value of a config or an experiment. A layer key needs a parameter. Add `.<param>` to read one parameter, e.g. `experiment:pricing.price`; string and number flags need a parameter. The `targetingKey` of the evaluation context is the `userID`. Fields such as `email`, `country`, `custom` and `customIDs` go to the fields of the `StatsigUser` with the same name.

[Statsig provider documentation](https://github.com/vercel/flags/tree/main/packages/adapter-statsig#openfeature-provider)

## LaunchDarkly

LaunchDarkly publishes an OpenFeature server provider; find it in the [OpenFeature ecosystem](https://openfeature.dev/ecosystem). The SDK knows the LaunchDarkly system, so a source can name its project. The [flags manifest](/docs/tooling/flags-manifest) then has the variables which tools need to link each flag to its targeting page in LaunchDarkly:

```ts title="flags/self.ts"
import { defineSource } from 'flags';
import { getEvaluationContext } from './context';
import { launchDarklyProvider } from './launchdarkly-provider';

export const launchdarkly = defineSource({
  // The OpenFeature server provider of LaunchDarkly
  provider: launchDarklyProvider,
  project: {
    system: 'launchdarkly',
    projectId: 'shop', // the key of the project
    teamId: 'acme',
    environment: 'production', // the key of the environment, for links
  },
  getEvaluationContext,
});
```

## Other providers

Many more flag management systems have an OpenFeature server provider for JavaScript. Search for your vendor in the [OpenFeature ecosystem](https://openfeature.dev/ecosystem), and use its provider as shown in [How to use a provider](#how-to-use-a-provider). Use a server provider (for Node.js), not a web provider: the Flags SDK evaluates flags on the server.

Your system has no OpenFeature provider? You can write one, see [Custom providers](/docs/providers/custom-providers).
