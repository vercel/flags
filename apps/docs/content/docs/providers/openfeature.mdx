Any [OpenFeature](https://openfeature.dev/) server provider works with the Flags SDK, as it is. This page lists providers which we know, with the package to install and a `defineSource` snippet for each. For providers which are not on this page, see the [OpenFeature ecosystem](https://openfeature.dev/ecosystem) (filter for server-side JavaScript providers).

<Callout>
The setup of each provider is a short summary of the documentation of the vendor. Options and package names can change. Check the documentation of the provider, linked in each section, for the options which you need in production.
</Callout>

## How to use a provider

The setup is the same for each provider.

### 1. Install the packages

Install `flags`, `@openfeature/server-sdk` (the peer dependency of most OpenFeature providers), and the provider:

```bash
npm install flags @openfeature/server-sdk @openfeature/flagd-provider
```

### 2. Create the evaluation context

Most OpenFeature providers identify the user by the `targetingKey` of the evaluation context. Create it once, from the request:

```ts title="context.ts"
import type { FlagsRequest } from 'flags';

export function getEvaluationContext(
  _input: unknown,
  request: FlagsRequest | undefined,
) {
  return {
    targetingKey: request?.cookies?.get('user-id')?.value ?? 'anonymous',
  };
}
```

The SDK gives no field a special meaning. Return what your provider needs, e.g. more attributes for its targeting rules. See [Evaluation context](/docs/flags/evaluation-context).

### 3. Define a source

```ts title="sources.ts"
import { FlagdProvider } from '@openfeature/flagd-provider';
import { defineSource } from 'flags';
import { getEvaluationContext } from './context';

export const flagd = defineSource({
  provider: new FlagdProvider(),
  getEvaluationContext,
});
```

### 4. Use it for your flags

Make it the default source:

```ts title="flags.config.ts"
import { defineConfig } from 'flags';
import { flagd } from './sources';

export const config = defineConfig({ defaultSource: flagd });

declare module 'flags' {
  interface Register {
    config: typeof config;
  }
}
```

Or name it in a flag:

```ts title="flags.ts"
'use flags';

import { bindFlag } from 'flags';
import { flagd } from './sources';

export const checkout = bindFlag({
  key: 'checkout',
  source: flagd,
  type: 'string',
  options: ['control', 'express'],
  defaultValue: 'control',
});
```

Do not call `OpenFeature.setProvider()`: the SDK calls the provider directly, and initializes it before the first evaluation. See [Providers](/docs/providers) for the lifecycle, and [OpenFeature compatibility](/docs/flags/openfeature) for hooks, events and tracking.

<Callout title="Providers which connect when you create them">
Tools import your `'use flags'` modules to read your flags, so creating a source must not open network connections. Most providers connect in `initialize()`. If a provider connects in its constructor or factory (below: CloudBees and Split), create the source in `flags.config.ts` as the `defaultSource`, or check the documentation of the provider for a lazy option.
</Callout>

## LaunchDarkly

LaunchDarkly publishes an OpenFeature server provider; find it in the [OpenFeature ecosystem](https://openfeature.dev/ecosystem). The SDK knows the LaunchDarkly system, so a source can name its project. The [flags manifest](/docs/tooling/flags-manifest) then has the variables which tools need to link each flag to its targeting page in LaunchDarkly:

```ts title="sources.ts"
import { defineSource } from 'flags';
import { getEvaluationContext } from './context';
import { launchDarklyProvider } from './launchdarkly-provider';

export const launchdarkly = defineSource({
  // The OpenFeature server provider of LaunchDarkly
  provider: launchDarklyProvider,
  project: {
    system: 'launchdarkly',
    projectId: 'shop', // the key of the project
    teamId: 'acme',
    environment: 'production', // the key of the environment, for links
  },
  getEvaluationContext,
});
```

## Other providers

Many more flag management systems have an OpenFeature server provider for JavaScript. Search for your vendor in the [OpenFeature ecosystem](https://openfeature.dev/ecosystem), and use its provider as shown in [How to use a provider](#how-to-use-a-provider). Use a server provider (for Node.js), not a web provider: the Flags SDK evaluates flags on the server.

Your system has no OpenFeature provider? You can write one, see [Custom providers](/docs/providers/custom-providers).
