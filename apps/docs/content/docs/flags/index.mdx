A flag is a function. You define it once, and call it on the server wherever you need its value:

```ts
const sale = await summerSale();
```

The same definition works in Next.js, SvelteKit, Nuxt, TanStack Start, Hono, Express and plain Node.js. Your application code imports only the `flags` package. The framework package only connects the SDK to the request of your framework (see [Frameworks](/docs/frameworks)).

## Two kinds of flags

The Flags SDK has two kinds of flags. Both return the same kind of function, and both get overrides from Flags Explorer, hooks, one value per request and type checks.

| | Inline flag | Flag of a source |
| --- | --- | --- |
| Defined with | `defineFlag` | `bindFlag` |
| The value comes from | your code, in `decide` | the OpenFeature provider of a source |
| Changed by | a deployment | your flag management system, at runtime |
| Needs | nothing | a source: a provider, optionally a project and an evaluation context |

### Inline flags

An inline flag decides its value in your code. It needs no provider and no account:

```ts title="flags.ts"
import { defineFlag } from 'flags';

export const betaBanner = defineFlag({
  key: 'beta-banner',
  decide: (request) => request?.cookies?.get('beta')?.value === '1',
});
```

See [Inline flags](/docs/flags/inline-flags).

### Flags of a source

A flag of a source gets its value from a flag management system, such as Vercel Flags or any other system with an OpenFeature provider. A source connects flags to that provider, and creates the evaluation context for it. By convention, the main source of an application is `self`.

In Next.js, SvelteKit, Nuxt and TanStack Start, you describe the source with two files in `flags/sources/self` (`provider.ts` and `catalog.ts`, and an optional `context.ts`), and import its flags from `flags:self`:

```ts title="flags/sources/self/provider.ts"
import { VercelProvider } from '@vercel/flags-core/openfeature';

export default new VercelProvider();
```

```ts title="app/page.tsx"
import { summerSale } from 'flags:self';

const sale = await summerSale();
```

The SDK [generates](/docs/flags/code-generation) the module of `flags:self` from the catalog of your flag management system. Without a bundler, or if you prefer, you write the same code by hand:

```ts title="flags/self.ts"
import { VercelProvider } from '@vercel/flags-core/openfeature';
import { bindFlag, defineSource } from 'flags';

export const self = defineSource({
  provider: new VercelProvider(),
  project: { system: 'vercel-flags' },
  getEvaluationContext: (request) => ({
    user: request?.cookies?.get('user')?.value ?? 'anonymous',
  }),
});

export const summerSale = bindFlag({
  key: 'summer-sale',
  source: self,
  defaultValue: false,
});
```

See [Flags of a source](/docs/flags/provider-flags).

## Which one to use

Use an **inline flag** when:

- the rule fits in a few lines of code, e.g. a cookie, a header, an environment variable or a row in your database;
- a change of the rule can wait for the next deployment;
- you want to start with flags before you choose a flag management system.

Use a **flag of a source** when:

- people other than developers change the flag, e.g. product managers in a dashboard;
- you need targeting rules, percentage rollouts or experiments;
- a change must apply without a deployment, e.g. a kill switch.

You can change your mind later. Both kinds of flags are called in the same way, so moving a flag from `defineFlag` to `bindFlag` does not change the code that calls it.

## One flag, everywhere

You call each flag in the same way, in a page, an API route, a middleware or a script:

```ts
await summerSale();
await teamInsights({ evaluationContext: { teamId: 'team-1' } });

const [sale, checkout] = await evaluate([summerSale, newCheckout]);
```

During one request, each flag is evaluated once, so all parts of a page see the same value. See [Evaluating flags](/docs/flags/evaluating-flags).

<Callout type="info">
  Flags run only on the server. Do not import `flags` in client code. Evaluate the flag on the server, and give the value to the client, e.g. as a prop.
</Callout>
